ข้อความจากผู้ใช้หลังคำสั่ง: $ARGUMENTS

คุณคือทีมพัฒนาระบบงานของทีม งานของคุณคือ **สร้าง tasks.md จาก spec.md และ plan.md** สำหรับฟีเจอร์ที่เลือก

## ขั้นที่ 0: หาไฟล์

- ถ้าผู้ใช้ระบุ path หลังคำสั่ง ให้ใช้ไฟล์นั้น
- ถ้าไม่ระบุ ให้หาไฟล์ `specs/*/spec.md` ถ้ามีหลายไฟล์ ให้ถามว่าจะใช้ไฟล์ไหน
- อ่าน `spec.md` และ `plan.md` ให้จบ
- ถ้า `spec.md` ยังเป็น `Draft v1` ให้แจ้งทีมว่ายังไม่ผ่าน clarify แล้วหยุด

## ขั้นที่ 1: สร้างไฟล์ tasks.md

สร้างไฟล์ `tasks.md` ในโฟลเดอร์เดียวกับ `spec.md` โดยมีโครงสร้างต่อไปนี้

### 1. หัวเรื่องและข้อมูลอ้างอิง
- ระบุเฉพาะชื่อฟีเจอร์และ spec ID
- ใส่ลิงก์ไปที่ `spec.md` และ `plan.md`

### 2. ลำดับงาน
- ทำตาราง `ลำดับ | งาน | รองรับ | สถานะ`
- เรียงงานตามลำดับที่ควรทำจริง
- ทุกงานต้องอ้าง FR / AC / Constraint / Open Question ที่เกี่ยวข้อง
- ห้ามเพิ่ม requirement ที่ไม่ได้ระบุใน spec

### 3. งานที่ต้องรอคำตอบ
- ถ้ามีงานที่เกี่ยวกับ Q-xx ให้ใส่สถานะ `รอ Q-xx` อย่างชัดเจน
- ห้ามเดาและทำต่อจนกว่าจะได้รับคำตอบ

### 4. ตารางครอบคลุม AC
- ต้องมีทุก AC ใน spec
- แต่ละแถวระบุ `AC ID` / `งานที่ตรวจ` / `สถานะ`

### 5. ตารางครอบคลุม Constraint
- ต้องมีทุก Constraint ใน spec ครบทุกตัว (CON, DOM, IF)
- แต่ละแถวระบุ `Constraint ID` / `งานที่รองรับ` / `สถานะ`
- ไม่มีช่องว่างหรือ constraint ที่ไม่มี task

## ขั้นที่ 2: รายงานทีม

หลังสร้างไฟล์แล้ว ให้สรุปสั้น ๆ ในแชต 3 เรื่อง
1. งานที่ยังถูก block จาก Open Question
2. AC ที่ทดสอบยากหรือไม่สามารถทดสอบได้ในสภาพแวดล้อมนักศึกษา
3. ส่วนที่จำเป็นต้องระวังเพื่อไม่ให้ AI เดา requirement เพิ่ม

แล้วเพิ่มบันทึกท้าย `prompt-log.md` ว่าใช้คำสั่ง `/tasks` และผลลัพธ์คืออะไร
