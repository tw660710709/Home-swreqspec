# Feature: จัดการบัญชีผู้ใช้ (Manage User Account)

Spec ID: SPEC-ACCOUNT-001 | Source: UC-08 | Use case: UC-08

Owner: ทีมพัฒนาระบบ | Status: Draft v2 | Updated: 2569-09-20

## Goal

ผู้พักอาศัย (Resident) สามารถดูและแก้ไขข้อมูลบัญชีส่วนตัว เช่น ชื่อ เบอร์โทรศัพท์ อีเมล และข้อมูลติดต่อ รวมถึงสามารถเปลี่ยนรหัสผ่านของตนเองได้อย่างถูกต้องและปลอดภัย โดยระบบต้องตรวจสอบข้อมูลก่อนบันทึกและแจ้งผลการดำเนินการให้ผู้ใช้ทราบ

## Scope

### In scope

- เปิดดูข้อมูลบัญชีและข้อมูลส่วนตัวของผู้ใช้
- แก้ไขข้อมูลส่วนตัว เช่น ชื่อ เบอร์โทรศัพท์ และอีเมล
- อัปเดตข้อมูลช่องทางติดต่อ
- เปลี่ยนรหัสผ่านของตนเอง
- ตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก
- ตรวจสอบรหัสผ่านเดิมก่อนเปลี่ยนรหัสผ่าน
- บันทึกข้อมูลใหม่ลงฐานข้อมูล
- ยกเลิกการแก้ไขและคืนค่าข้อมูลเดิม
- แสดงข้อความแจ้งเตือนเมื่อบันทึกข้อมูลสำเร็จหรือข้อมูลไม่ถูกต้อง

### Out of scope

- การสมัครสมาชิก
- การเข้าสู่ระบบ ซึ่งอยู่ใน `UC-07`
- การจัดการข้อมูลบัญชีของผู้ใช้อื่น
- การเปลี่ยน role ของผู้ใช้
- การลบบัญชีผู้ใช้
- การจัดการข้อมูลหอพัก
- การรีเซ็ตรหัสผ่านกรณีผู้ใช้ลืมรหัสผ่าน

## Constraints

- CON-ACCOUNT-01 ผู้ใช้ต้องเข้าสู่ระบบก่อนจึงจะสามารถจัดการบัญชีของตนเองได้
- CON-ACCOUNT-02 ผู้ใช้สามารถแก้ไขได้เฉพาะข้อมูลบัญชีของตนเอง
- CON-ACCOUNT-03 ระบบต้องตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก
- CON-ACCOUNT-04 การเปลี่ยนรหัสผ่านต้องตรวจสอบรหัสผ่านเดิมก่อน
- CON-SEC-01 รหัสผ่านต้องไม่ถูกจัดเก็บเป็น plain text
- CON-SEC-02 รหัสผ่านใหม่ต้องได้รับการปกป้องอย่างเหมาะสมก่อนบันทึก
- CON-UI-01 หน้าจัดการบัญชีผู้ใช้ต้องรองรับการใช้งานบนอุปกรณ์ที่ระบบรองรับ

## Requirements

- FR-ACCOUNT-01 ระบบต้องแสดงข้อมูลบัญชีปัจจุบันของ Resident ที่เข้าสู่ระบบแล้ว
  <- UC-08 main flow ขั้น 1-2

- FR-ACCOUNT-02 ระบบต้องให้ Resident แก้ไขข้อมูลส่วนตัว เช่น ชื่อ เบอร์โทรศัพท์ อีเมล และข้อมูลติดต่อ
  <- UC-08 main flow ขั้น 3

- FR-ACCOUNT-03 ระบบต้องตรวจสอบความถูกต้องและรูปแบบของข้อมูลก่อนบันทึก
  <- UC-08 main flow ขั้น 5, exception 5a

- FR-ACCOUNT-04 ระบบต้องบันทึกข้อมูลบัญชีใหม่ลงฐานข้อมูลเมื่อข้อมูลผ่านการตรวจสอบ
  <- UC-08 main flow ขั้น 6

- FR-ACCOUNT-05 ระบบต้องแสดงข้อความแจ้งเตือนเมื่อบันทึกข้อมูลบัญชีสำเร็จ และแสดงข้อมูลล่าสุดบนหน้าโปรไฟล์
  <- UC-08 main flow ขั้น 7

- FR-ACCOUNT-06 ระบบต้องรองรับการเปลี่ยนรหัสผ่าน โดยให้ผู้ใช้กรอกรหัสผ่านเดิม รหัสผ่านใหม่ และยืนยันรหัสผ่านใหม่
  <- UC-08 alternative 3a

- FR-ACCOUNT-07 ระบบต้องตรวจสอบรหัสผ่านเดิมก่อนอนุญาตให้เปลี่ยนรหัสผ่าน
  <- UC-08 alternative 3a, exception 5b

- FR-ACCOUNT-08 ระบบต้องไม่บันทึกการเปลี่ยนแปลงเมื่อผู้ใช้ยกเลิกการแก้ไข
  <- UC-08 alternative 4a

- FR-ACCOUNT-09 ระบบต้องปฏิเสธการเข้าถึงหน้าจัดการบัญชีหากผู้ใช้ไม่มี session ที่ใช้งานได้
  <- UC-08 precondition

## Quality Requirements

- NFR-USE-01 หน้าจัดการบัญชีผู้ใช้ต้องใช้งานง่ายและไม่ซับซ้อน โดยแบ่งข้อมูลส่วนตัวและการเปลี่ยนรหัสผ่านอย่างชัดเจน

- NFR-PERF-01 ระบบต้องประมวลผลและอัปเดตข้อมูลบัญชีภายใน 2 วินาทีภายใต้สภาวะการใช้งานปกติ

- NFR-SEC-01 รหัสผ่านใหม่ต้องไม่ถูกจัดเก็บเป็น plain text และต้องได้รับการปกป้องตามมาตรฐานความปลอดภัยก่อนบันทึก

- NFR-SEC-02 ระบบต้องตรวจสอบ session และอนุญาตให้ผู้ใช้แก้ไขเฉพาะบัญชีของตนเอง

## Acceptance Criteria

- [ ] AC-ACCOUNT-01 (FR-ACCOUNT-01, FR-ACCOUNT-02, FR-ACCOUNT-04)

      Given Resident เข้าสู่ระบบและเปิดหน้าจัดการบัญชี

      When ผู้ใช้แก้ไขข้อมูลส่วนตัว เช่น ชื่อ เบอร์โทรศัพท์ หรืออีเมล แล้วกดบันทึก

      Then ระบบต้องตรวจสอบและบันทึกข้อมูลใหม่ลงฐานข้อมูล และแสดงข้อมูลล่าสุดบนหน้าโปรไฟล์

- [ ] AC-ACCOUNT-02 (FR-ACCOUNT-06, FR-ACCOUNT-07)

      Given Resident ต้องการเปลี่ยนรหัสผ่าน

      When ผู้ใช้กรอกรหัสผ่านเดิมที่ถูกต้อง รหัสผ่านใหม่ และยืนยันรหัสผ่านใหม่ตรงกัน

      Then ระบบต้องเปลี่ยนรหัสผ่านและบันทึกข้อมูลใหม่อย่างปลอดภัย

- [ ] AC-ACCOUNT-03 (FR-ACCOUNT-03)

      Given ผู้ใช้กรอกข้อมูลที่ไม่ครบถ้วนหรือไม่ถูกต้องตามรูปแบบ

      When ผู้ใช้กดบันทึก

      Then ระบบต้องไม่บันทึกข้อมูล และแสดงข้อความแจ้งเตือนในจุดที่ผิดพลาด

- [ ] AC-ACCOUNT-04 (FR-ACCOUNT-07)

      Given ผู้ใช้ต้องการเปลี่ยนรหัสผ่านแต่กรอกรหัสผ่านเดิมไม่ถูกต้อง

      When ผู้ใช้ยืนยันการเปลี่ยนรหัสผ่าน

      Then ระบบต้องไม่เปลี่ยนรหัสผ่าน และแจ้งว่ารหัสผ่านเดิมไม่ถูกต้อง

- [ ] AC-ACCOUNT-05 (FR-ACCOUNT-05)

      Given ผู้ใช้กรอกข้อมูลถูกต้องและระบบบันทึกสำเร็จ

      When ระบบดำเนินการอัปเดตข้อมูลเสร็จสิ้น

      Then ระบบต้องแสดงข้อความยืนยันว่าบันทึกข้อมูลสำเร็จ

- [ ] AC-ACCOUNT-06 (FR-ACCOUNT-08)

      Given ผู้ใช้กำลังแก้ไขข้อมูลบัญชี

      When ผู้ใช้กดยกเลิก

      Then ระบบต้องไม่บันทึกข้อมูลที่แก้ไข และแสดงข้อมูลเดิมกลับมา

- [ ] AC-ACCOUNT-07 (FR-ACCOUNT-09)

      Given ผู้ใช้ไม่มี session ที่ใช้งานได้

      When ผู้ใช้พยายามเปิดหน้าจัดการบัญชี

      Then ระบบต้องไม่อนุญาตให้เข้าถึง และนำผู้ใช้ไปยังหน้า Login

- [ ] AC-ACCOUNT-08 (NFR-PERF-01)

      Given ระบบอยู่ในสภาวะการใช้งานปกติ

      When ผู้ใช้บันทึกข้อมูลบัญชี

      Then ระบบต้องประมวลผลและตอบสนองภายใน 2 วินาที

## Assumptions & Open Questions

- ASM-01 ผู้ใช้ของ UC-08 เป็น Resident ที่เข้าสู่ระบบแล้ว
- ASM-02 ข้อมูลบัญชีที่แสดงในหน้า Manage Account เป็นข้อมูลของผู้ใช้ที่กำลังเข้าสู่ระบบ
- ASM-03 ระบบมี session หรือ authentication mechanism สำหรับตรวจสอบตัวตนของผู้ใช้
- ASM-04 เบอร์โทรศัพท์และอีเมลต้องผ่านรูปแบบ validation ที่ระบบกำหนด
- ASM-05 การเปลี่ยนรหัสผ่านต้องใช้รหัสผ่านเดิมเพื่อยืนยันตัวตน
- ASM-06 การรีเซ็ตรหัสผ่านกรณีลืมรหัสผ่านไม่อยู่ในขอบเขตของ UC-08

### Open Questions

- รูปแบบและจำนวนหลักของเบอร์โทรศัพท์จะกำหนดเป็นมาตรฐานใด
- อีเมลที่แก้ไขใหม่จำเป็นต้องยืนยันผ่านอีเมลหรือไม่
- รหัสผ่านใหม่ต้องมีเงื่อนไขด้านความยาวและความซับซ้อนระดับใด
- หลังเปลี่ยนรหัสผ่านสำเร็จ session เดิมจะยังคงใช้งานอยู่หรือไม่
