# Feature: จัดการบัญชีผู้ใช้ (Manage User Account)

Spec ID: SPEC-ACCOUNT-001 | Source: UC-08 | Use case: UC-08

Owner: ทีมพัฒนาระบบ | Status: Draft v2 | Updated: 2569-11-13

## Goal

ผู้พักอาศัย (Resident) สามารถดูและแก้ไขชื่อ เบอร์โทรศัพท์ และอีเมลของตนเอง รวมถึงเปลี่ยนรหัสผ่านได้ โดยระบบต้องตรวจสอบข้อมูลก่อนบันทึกและแจ้งผลการดำเนินการให้ผู้ใช้ทราบ

## Scope

### In scope

- เปิดดูข้อมูลบัญชีและข้อมูลส่วนตัวของผู้ใช้
- แก้ไขชื่อ เบอร์โทรศัพท์ และอีเมล
- เปลี่ยนรหัสผ่านของตนเอง
- ตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก
- ตรวจสอบรหัสผ่านเดิมก่อนเปลี่ยนรหัสผ่าน
- บันทึกข้อมูลใหม่ลงฐานข้อมูล
- ยกเลิกการแก้ไขและคืนค่าข้อมูลเดิม
- แสดงข้อความแจ้งเตือนเมื่อบันทึกข้อมูลสำเร็จหรือข้อมูลไม่ถูกต้อง

### Out of scope

- การสมัครสมาชิก
- การเข้าสู่ระบบ ซึ่งอยู่ใน `UC-07`
- การจัดการข้อมูลบัญชีของผู้ใช้อื่น
- การเปลี่ยน role ของผู้ใช้
- การลบบัญชีผู้ใช้
- การจัดการข้อมูลหอพัก
- การรีเซ็ตรหัสผ่านกรณีผู้ใช้ลืมรหัสผ่าน
- การยืนยันอีเมลใหม่

## Constraints

- CON-ACCOUNT-01 ผู้ใช้ต้องเข้าสู่ระบบก่อนจึงจะสามารถจัดการบัญชีของตนเองได้
- CON-ACCOUNT-02 ผู้ใช้สามารถแก้ไขได้เฉพาะข้อมูลบัญชีของตนเอง โดยอ้างอิงตัวตนที่ผ่านการตรวจสอบ
- CON-ACCOUNT-03 ระบบต้องตรวจสอบความถูกต้องของข้อมูลก่อนบันทึก
- CON-ACCOUNT-04 การเปลี่ยนรหัสผ่านต้องตรวจสอบรหัสผ่านเดิมก่อน
- CON-SEC-01 รหัสผ่านต้องไม่ถูกจัดเก็บเป็น plain text
- CON-SEC-02 รหัสผ่านใหม่ต้องจัดเก็บเป็น salted password hash เช่น Argon2 หรือ bcrypt และข้อมูลต้องรับส่งผ่าน HTTPS
- CON-UI-01 หน้าจัดการบัญชีผู้ใช้ต้องรองรับหน้าจอมือถือ แท็บเล็ต และคอมพิวเตอร์ โดยปรับรูปแบบตามขนาดหน้าจอ

## Requirements

- FR-ACCOUNT-01 ระบบต้องแสดงข้อมูลบัญชีปัจจุบันของ Resident ที่เข้าสู่ระบบแล้ว
  <- UC-08 main flow ขั้น 1-2

- FR-ACCOUNT-02 ระบบต้องให้ Resident แก้ไขชื่อ เบอร์โทรศัพท์ และอีเมลของตนเอง โดยไม่ต้องยืนยันอีเมลใหม่ใน UC-08
  <- UC-08 main flow ขั้น 3

- FR-ACCOUNT-03 ระบบต้องตรวจสอบข้อมูลก่อนบันทึก โดยเบอร์โทรศัพท์ต้องเป็นตัวเลข 10 หลัก อีเมลต้องมีรูปแบบอีเมลที่ถูกต้อง และรหัสผ่านใหม่ต้องตรงกับช่องยืนยันรหัสผ่านใหม่
  <- UC-08 main flow ขั้น 5, exception 5a

- FR-ACCOUNT-04 ระบบต้องบันทึกข้อมูลบัญชีใหม่ลงฐานข้อมูลเมื่อข้อมูลผ่านการตรวจสอบ
  <- UC-08 main flow ขั้น 6

- FR-ACCOUNT-05 ระบบต้องแสดงข้อความแจ้งเตือนเมื่อบันทึกข้อมูลบัญชีสำเร็จ และแสดงข้อมูลล่าสุดบนหน้าโปรไฟล์
  <- UC-08 main flow ขั้น 7

- FR-ACCOUNT-06 ระบบต้องรองรับการเปลี่ยนรหัสผ่าน โดยให้ผู้ใช้กรอกรหัสผ่านเดิม รหัสผ่านใหม่ที่มีความยาวอย่างน้อย 8 ตัวอักษร และยืนยันรหัสผ่านใหม่
  <- UC-08 alternative 3a

- FR-ACCOUNT-07 ระบบต้องตรวจสอบรหัสผ่านเดิมก่อนอนุญาตให้เปลี่ยนรหัสผ่าน
  <- UC-08 alternative 3a, exception 5b

- FR-ACCOUNT-08 ระบบต้องไม่บันทึกการเปลี่ยนแปลงข้อมูลส่วนตัวเมื่อผู้ใช้ยกเลิกการแก้ไข โดยการเปลี่ยนรหัสผ่านเป็นกระบวนการแยกต่างหาก
  <- UC-08 alternative 4a

- FR-ACCOUNT-09 ระบบต้องปฏิเสธการเข้าถึงหน้าจัดการบัญชีหากผู้ใช้ไม่มี session ที่ใช้งานได้ และนำผู้ใช้ไปยังหน้า Login
  <- UC-08 precondition

## Quality Requirements

- NFR-USE-01 หน้าจัดการบัญชีผู้ใช้ต้องใช้งานง่ายและไม่ซับซ้อน โดยแบ่งข้อมูลส่วนตัวและการเปลี่ยนรหัสผ่านอย่างชัดเจน และปรับรูปแบบตามขนาดหน้าจอมือถือ แท็บเล็ต และคอมพิวเตอร์

- NFR-PERF-01 ระบบต้องแสดงผลสำเร็จหรือข้อผิดพลาดภายใน 2 วินาที โดยเริ่มจับเวลาตั้งแต่ผู้ใช้กดบันทึก ภายใต้สภาพแวดล้อมทดสอบปกติ

- NFR-SEC-01 รหัสผ่านใหม่ต้องไม่ถูกจัดเก็บเป็น plain text และต้องจัดเก็บเป็น salted password hash เช่น Argon2 หรือ bcrypt

- NFR-SEC-02 ระบบต้องตรวจสอบตัวตนจาก session/token ฝั่ง server และอนุญาตให้ผู้ใช้แก้ไขเฉพาะบัญชีของตนเอง หากผู้ใช้มีตัวตนแต่ไม่มีสิทธิ์ต้องปฏิเสธด้วย HTTP 403

## Acceptance Criteria

- [ ] AC-ACCOUNT-01 (FR-ACCOUNT-01, FR-ACCOUNT-02, FR-ACCOUNT-04, FR-ACCOUNT-05, NFR-USE-01, CON-UI-01)

      Given Resident เข้าสู่ระบบและเปิดหน้าจัดการบัญชี

      When ผู้ใช้แก้ไขข้อมูลส่วนตัว เช่น ชื่อ เบอร์โทรศัพท์ หรืออีเมล แล้วกดบันทึก

      Then ระบบต้องตรวจสอบและบันทึกข้อมูลใหม่ลงฐานข้อมูล และแสดงข้อมูลล่าสุดบนหน้าโปรไฟล์

      กรณีเปิดหน้าจัดการบัญชี:

      Given Resident เปิดหน้าจัดการบัญชีบนมือถือ แท็บเล็ต หรือคอมพิวเตอร์

      When ระบบแสดงหน้าจัดการบัญชี

      Then ระบบต้องแสดงข้อมูลบัญชีปัจจุบัน แบ่งส่วนข้อมูลส่วนตัวและการเปลี่ยนรหัสผ่านอย่างชัดเจน และปรับรูปแบบตามขนาดหน้าจอ

- [ ] AC-ACCOUNT-02 (FR-ACCOUNT-06, FR-ACCOUNT-07, NFR-SEC-01, CON-SEC-01, CON-SEC-02)

      Given Resident ต้องการเปลี่ยนรหัสผ่าน

      When ผู้ใช้กรอกรหัสผ่านเดิมที่ถูกต้อง รหัสผ่านใหม่ที่มีความยาวอย่างน้อย 8 ตัวอักษร และยืนยันรหัสผ่านใหม่ตรงกัน

      Then ระบบต้องเปลี่ยนรหัสผ่านและจัดเก็บเป็น salted password hash ไม่ใช่ plain text โดยรับส่งข้อมูลผ่าน HTTPS จากนั้นยกเลิก session เดิมและนำผู้ใช้ไปยังหน้า Login

- [ ] AC-ACCOUNT-03 (FR-ACCOUNT-03, FR-ACCOUNT-06)

      Given ผู้ใช้กรอกข้อมูลบัญชีที่ไม่ครบถ้วนหรือไม่ถูกต้องตามรูปแบบ เช่น เบอร์โทรศัพท์ไม่เป็นตัวเลข 10 หลักหรืออีเมลไม่ถูกต้อง

      When ผู้ใช้กดบันทึก

      Then ระบบต้องไม่บันทึกข้อมูล และแสดงข้อความแจ้งเตือนในจุดที่ผิดพลาด

      กรณียืนยันรหัสผ่านใหม่ไม่ตรงกัน:

      Given ผู้ใช้กรอกรหัสผ่านใหม่และยืนยันรหัสผ่านใหม่ไม่ตรงกัน

      When ผู้ใช้ยืนยันการเปลี่ยนรหัสผ่าน

      Then ระบบต้องไม่บันทึกการเปลี่ยนรหัสผ่าน และแจ้งข้อผิดพลาด

      กรณีรหัสผ่านใหม่สั้นกว่า 8 ตัวอักษร:

      Given ผู้ใช้กรอกรหัสผ่านใหม่ที่มีความยาวน้อยกว่า 8 ตัวอักษร

      When ผู้ใช้ยืนยันการเปลี่ยนรหัสผ่าน

      Then ระบบต้องไม่บันทึกการเปลี่ยนรหัสผ่าน และแจ้งข้อผิดพลาด

- [ ] AC-ACCOUNT-04 (FR-ACCOUNT-07)

      Given ผู้ใช้ต้องการเปลี่ยนรหัสผ่านแต่กรอกรหัสผ่านเดิมไม่ถูกต้อง

      When ผู้ใช้ยืนยันการเปลี่ยนรหัสผ่าน

      Then ระบบต้องไม่เปลี่ยนรหัสผ่าน และแจ้งว่ารหัสผ่านเดิมไม่ถูกต้อง

- [ ] AC-ACCOUNT-05 (FR-ACCOUNT-05)

      Given ผู้ใช้กรอกข้อมูลถูกต้องและระบบบันทึกสำเร็จ

      When ระบบดำเนินการอัปเดตข้อมูลเสร็จสิ้น

      Then ระบบต้องแสดงข้อความยืนยันว่าบันทึกข้อมูลสำเร็จ

- [ ] AC-ACCOUNT-06 (FR-ACCOUNT-08)

      Given ผู้ใช้กำลังแก้ไขข้อมูลส่วนตัว

      When ผู้ใช้กดยกเลิก

      Then ระบบต้องไม่บันทึกข้อมูลที่แก้ไข และแสดงข้อมูลส่วนตัวเดิมกลับมา โดยไม่ยกเลิกหรือเปลี่ยนแปลงกระบวนการเปลี่ยนรหัสผ่าน

- [ ] AC-ACCOUNT-07 (FR-ACCOUNT-09, NFR-SEC-02, CON-ACCOUNT-01, CON-ACCOUNT-02)

      Given ผู้ใช้ไม่มี session ที่ใช้งานได้

      When ผู้ใช้พยายามเปิดหน้าจัดการบัญชี

      Then ระบบต้องไม่อนุญาตให้เข้าถึง และนำผู้ใช้ไปยังหน้า Login

      กรณีมี session/token แต่ไม่มีสิทธิ์:

      Given ผู้ใช้มี session/token ที่ตรวจสอบตัวตนได้

      When ผู้ใช้พยายามเข้าถึงหรือแก้ไขบัญชีของผู้ใช้อื่น

      Then ระบบต้องปฏิเสธคำขอด้วย HTTP 403 และไม่เปลี่ยนแปลงข้อมูลบัญชีนั้น

- [ ] AC-ACCOUNT-08 (NFR-PERF-01)

      Given ระบบอยู่ในสภาพแวดล้อมทดสอบปกติ

      When ผู้ใช้กดบันทึกข้อมูลบัญชีและเริ่มจับเวลา

      Then ระบบต้องแสดงผลสำเร็จหรือข้อผิดพลาดภายใน 2 วินาที

## Assumptions & Open Questions

- ASM-01 ผู้ใช้ของ UC-08 เป็น Resident ที่เข้าสู่ระบบแล้ว
- ASM-02 ข้อมูลบัญชีที่แสดงในหน้า Manage Account เป็นข้อมูลของผู้ใช้ที่กำลังเข้าสู่ระบบ
- ASM-03 ระบบมี session/token ที่ตรวจสอบตัวตนฝั่ง server ได้
- ASM-04 ฟิลด์ที่แก้ไขได้คือชื่อ เบอร์โทรศัพท์ และอีเมล โดยเบอร์โทรศัพท์ประกอบด้วยตัวเลข 10 หลัก อีเมลมีรูปแบบถูกต้อง และไม่ต้องยืนยันอีเมลใหม่ใน UC-08
- ASM-05 การเปลี่ยนรหัสผ่านต้องใช้รหัสผ่านเดิมเพื่อยืนยันตัวตน
- ASM-06 การรีเซ็ตรหัสผ่านกรณีลืมรหัสผ่านไม่อยู่ในขอบเขตของ UC-08

### Open Questions

- Q-01 ชื่อ เบอร์โทรศัพท์ และอีเมล จำเป็นต้องกรอกทุกฟิลด์หรือไม่ และชื่อมีเงื่อนไขการตรวจสอบเพิ่มเติมหรือไม่ (ทีมผู้กำหนด UC-08)
- Q-02 จะใช้เกณฑ์ใดประเมินว่า NFR-USE-01 ใช้งานง่ายและไม่ซับซ้อน (ทีมเอง)
- Q-03 สภาพแวดล้อมทดสอบปกติสำหรับ NFR-PERF-01 มีเงื่อนไขด้านเครือข่ายหรือปริมาณการใช้งานอย่างไร (ทีมเอง)
