# Feature: ตรวจสอบและอนุมัติหอพัก

Spec ID: SPEC-ADM-001 | Source: UC-13 | Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-20

## Goal

ให้ Admin สามารถตรวจสอบข้อมูลและเอกสารของหอพักที่เจ้าของหอพักส่งเข้ามา ก่อนอนุมัติให้เผยแพร่ในระบบ โดย Admin สามารถอนุมัติ ขอให้แก้ไข หรือปฏิเสธ พร้อมบันทึกประวัติการตรวจสอบและแจ้งผลให้เจ้าของหอพักทราบ

---

## Scope

### In scope

* แสดงรายการหอพักที่รอการตรวจสอบ
* แสดงรายละเอียดข้อมูลหอพัก
* แสดงเอกสารประกอบของหอพัก
* ตรวจสอบความครบถ้วนของข้อมูลและเอกสาร
* อนุมัติหอพัก
* ขอให้เจ้าของหอพักแก้ไขข้อมูล
* ปฏิเสธหอพักพร้อมระบุเหตุผล
* เปลี่ยนสถานะของหอพักตามผลการตรวจสอบ
* บันทึกประวัติการตรวจสอบ
* แจ้งผลการตรวจสอบให้เจ้าของหอพัก
* ตรวจสอบสิทธิ์ของ Admin ก่อนดำเนินการ

### Out of scope

* การจัดการข้อมูลหอพัก → UC-03 จัดการข้อมูลหอพัก
* การอัปเดตสถานะห้องว่าง → UC-04 อัปเดตสถานะห้องว่าง
* การดูสถิติหอพัก → UC-05 ดูสถิติหอพัก
* การค้นหาและดูข้อมูลหอพักสำหรับผู้ใช้งานทั่วไป → UC-01 ค้นหาและดูข้อมูลหอพัก
* การจัดการบัญชีผู้ใช้ → UC-08 จัดการบัญชีผู้ใช้

---

## Constraints

* CON-ADM-01: เฉพาะผู้ใช้ที่มีสิทธิ์ Admin เท่านั้นที่สามารถตรวจสอบและอนุมัติหอพักได้
* CON-ADM-02: หอพักที่มีข้อมูลหรือเอกสารไม่ครบไม่สามารถอนุมัติได้
* CON-ADM-03: การขอแก้ไขหรือปฏิเสธต้องระบุเหตุผล
* CON-ADM-04: ทุกการตรวจสอบต้องมีประวัติผู้ดำเนินการ วันที่ เวลา ผลการดำเนินการ และเหตุผล
* CON-ADM-05: หอพักที่มีสถานะ Approved เท่านั้นจึงจะแสดงต่อผู้ใช้งานทั่วไป
* CON-ADM-06: เมื่อถูกขอให้แก้ไข เจ้าของหอพักสามารถแก้ไขข้อมูลและส่งตรวจสอบใหม่ได้
* CON-ADM-07: หากไม่สามารถบันทึกผลการตรวจสอบได้ ระบบต้องแจ้งข้อผิดพลาดและไม่เปลี่ยนสถานะของหอพัก

---

## Requirements

### Functional Requirements

* FR-ADM-01: ระบบต้องแสดงรายการหอพักที่มีสถานะ Pending Review ให้ Admin
* FR-ADM-02: ระบบต้องแสดงรายละเอียดข้อมูลและเอกสารของหอพักที่ Admin เลือกตรวจสอบ
* FR-ADM-03: ระบบต้องตรวจสอบว่าข้อมูลและเอกสารที่จำเป็นครบถ้วนก่อนอนุมัติ
* FR-ADM-04: Admin สามารถอนุมัติหอพักได้เมื่อข้อมูลและเอกสารครบถ้วน
* FR-ADM-05: Admin สามารถขอให้เจ้าของหอพักแก้ไขข้อมูล พร้อมระบุเหตุผล
* FR-ADM-06: Admin สามารถปฏิเสธหอพัก พร้อมระบุเหตุผล
* FR-ADM-07: ระบบต้องเปลี่ยนสถานะหอพักตามผลการตรวจสอบ ได้แก่ Pending Review, Approved, Need Revision และ Rejected
* FR-ADM-08: ระบบต้องบันทึกประวัติการตรวจสอบทุกครั้ง
* FR-ADM-09: ระบบต้องแจ้งผลการตรวจสอบให้เจ้าของหอพักทราบ
* FR-ADM-10: ระบบต้องตรวจสอบสิทธิ์ของผู้ใช้งานก่อนเข้าถึงฟังก์ชันตรวจสอบหอพัก

---

## Quality Requirements

* NFR-SEC-01: ข้อมูลหอพักและเอกสารต้องสามารถเข้าถึงได้เฉพาะผู้ที่มีสิทธิ์
* NFR-AUD-01: ระบบต้องเก็บประวัติการตรวจสอบเพื่อให้สามารถตรวจสอบย้อนหลังได้
* NFR-DATA-01: สถานะหอพักและประวัติการตรวจสอบต้องสอดคล้องกัน
* NFR-USE-01: หน้าจอตรวจสอบต้องแสดงข้อมูล สถานะ และผลการดำเนินการอย่างชัดเจน

---

## Acceptance Criteria

### AC-ADM-01: Admin สามารถตรวจสอบข้อมูลหอพัก

**Given** มีหอพักที่อยู่ในสถานะ Pending Review
**When** Admin เปิดรายการหอพักและเลือกหอพักรายการหนึ่ง
**Then** ระบบต้องแสดงรายละเอียดข้อมูลและเอกสารของหอพักนั้น

### AC-ADM-02: Admin สามารถอนุมัติหอพัก

**Given** ข้อมูลและเอกสารของหอพักครบถ้วน
**When** Admin เลือกอนุมัติ
**Then** ระบบต้องเปลี่ยนสถานะหอพักเป็น Approved และบันทึกประวัติการอนุมัติ

### AC-ADM-03: Admin สามารถขอให้แก้ไขข้อมูล

**Given** Admin พบว่าข้อมูลบางส่วนต้องแก้ไข
**When** Admin เลือกขอให้แก้ไขและระบุเหตุผล
**Then** ระบบต้องเปลี่ยนสถานะเป็น Need Revision และแจ้งเหตุผลให้เจ้าของหอพักทราบ

### AC-ADM-04: Admin สามารถปฏิเสธหอพัก

**Given** Admin พบว่าหอพักไม่ผ่านเงื่อนไข
**When** Admin เลือกปฏิเสธและระบุเหตุผล
**Then** ระบบต้องเปลี่ยนสถานะเป็น Rejected และแจ้งผลให้เจ้าของหอพักทราบ

### AC-ADM-05: ระบบต้องบันทึกประวัติการตรวจสอบ

**Given** Admin ดำเนินการอนุมัติ ขอแก้ไข หรือปฏิเสธ
**When** ระบบบันทึกผลการตรวจสอบ
**Then** ต้องมีข้อมูล Admin ผู้ดำเนินการ วันที่ เวลา ผลการดำเนินการ และเหตุผล

### AC-ADM-06: ระบบต้องไม่อนุมัติข้อมูลที่ไม่ครบ

**Given** ข้อมูลหรือเอกสารที่จำเป็นของหอพักไม่ครบ
**When** Admin พยายามอนุมัติ
**Then** ระบบต้องแจ้งว่าข้อมูลไม่ครบและไม่อนุมัติหอพัก

### AC-ADM-07: ผู้ที่ไม่มีสิทธิ์ Admin ไม่สามารถตรวจสอบหอพัก

**Given** ผู้ใช้งานไม่มีสิทธิ์ Admin
**When** พยายามเข้าถึงหน้าตรวจสอบหอพัก
**Then** ระบบต้องปฏิเสธการเข้าถึง

### AC-ADM-08: ระบบต้องจัดการกรณีบันทึกผลไม่สำเร็จ

**Given** เกิดข้อผิดพลาดขณะบันทึกผลการตรวจสอบ
**When** ระบบไม่สามารถบันทึกข้อมูลได้
**Then** ระบบต้องแจ้งข้อผิดพลาดและไม่เปลี่ยนสถานะหอพักจนกว่าจะบันทึกสำเร็จ

## Assumptions & Open Questions

### Assumptions

* ASM-01: เมื่อ Admin ขอให้แก้ไขข้อมูล สถานะหอพักจะเปลี่ยนเป็น `Need Revision`
* ASM-02: ระบบใช้ Notification ภายในระบบในการแจ้งผลให้เจ้าของหอพัก
* ASM-03: ประวัติการตรวจสอบจะเก็บ Admin ผู้ดำเนินการ วันที่ เวลา ผลการดำเนินการ และเหตุผล
* ASM-04: เจ้าของหอพักสามารถแก้ไขข้อมูลและส่งตรวจสอบใหม่ได้เมื่อสถานะเป็น `Need Revision`
* ASM-05: หอพักที่มีสถานะ `Approved` เท่านั้นจึงจะแสดงในส่วนของผู้ใช้งานทั่วไป

### Open Questions

* ไม่มีในขอบเขตของ UC-13 ณ เวอร์ชันนี้
