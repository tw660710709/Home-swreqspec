# Feature: แจ้งซ่อมและรายงานปัญหา (Report Repair & Issues)
Spec ID: SPEC-REP-010 | Source: ข้อมูลแจ้งซ่อมจากผู้พักอาศัย | Use case: UC-10  
Owner: ทีมพัฒนาระบบหอพัก | Status: Draft v2 | Updated: 2569-11-18

## Goal
ผู้พักอาศัยสามารถแจ้งปัญหาหรือสิ่งของชำรุดภายในห้องพัก พร้อมแนบรูปภาพประกอบ และสามารถตรวจสอบสถานะการดำเนินงานได้อย่างชัดเจน โดยระบบต้องบันทึกข้อมูลและตอบสนองสำเร็จด้วยค่า p95 <= 2 วินาที เพื่อให้เจ้าของหอพักรับทราบและดำเนินการแก้ไขได้อย่างรวดเร็ว

## Scope

### In scope
- การเลือกประเภทปัญหาและกรอกรายละเอียดเพิ่มเติม
- การแนบไฟล์รูปภาพประกอบการแจ้งซ่อม
- การตรวจสอบความครบถ้วนของข้อมูลและขนาด/ประเภทไฟล์รูปภาพ
- การบันทึกข้อมูลการแจ้งซ่อมและการแสดงรายการพร้อมสถานะการซ่อมปัจจุบันของผู้พักอาศัย

### Out of scope
- การจัดการและอัปเดตสถานะการซ่อมโดยเจ้าของหอพักหรือช่างซ่อม (ฟีเจอร์จัดการหอพักของเจ้าของหอพัก)
- การประเมินความพึงพอใจหลังการซ่อมแซม
- การออกใบเสร็จหรือเก็บค่าใช้จ่ายเพิ่มเติมจากการซ่อมแซม

## Constraints
- CON-SYS-01: ผู้ใช้ต้องเข้าสู่ระบบเรียบร้อยแล้ว และมีสิทธิ์เป็นผู้พักอาศัย (Resident) ของห้องพักนั้นๆ จึงจะสามารถใช้งานฟีเจอร์นี้ได้ (อ้างอิงกลไกจำลองสิทธิ์ตาม ASM-05 ระหว่างที่ UC-07 ยังไม่มีการพัฒนา)
- CON-UI-01: แบบฟอร์มและหน้ารายการแจ้งซ่อมต้องรองรับการแสดงผลแบบ Responsive ที่ความกว้างหน้าจอโทรศัพท์ (375px) แท็บเล็ต (768px) และเดสก์ท็อป (1280px)

## Requirements
- FR-REP-01: ระบบต้องแสดงแบบฟอร์มให้ผู้ใช้เลือกประเภทปัญหาจากรายการที่กำหนด (ไฟฟ้า, ประปา, เฟอร์นิเจอร์/อุปกรณ์, อื่นๆ) และกรอกรายละเอียดปัญหาเพิ่มเติม (ความยาว 1–1,000 ตัวอักษร) <- UC-10 main flow ขั้น 2-3, alternative 3a
- FR-REP-02: ระบบต้องรองรับการอัปโหลดไฟล์รูปภาพประกอบปัญหาแบบไม่บังคับ (Optional) สูงสุดไม่เกิน 3 รูปต่อ 1 รายการแจ้งซ่อม <- UC-10 main flow ขั้น 4, alternative 4a
- FR-REP-03: ระบบต้องมีปุ่มยืนยันการแจ้งซ่อมสำหรับส่งข้อมูล และปุ่มยกเลิกซึ่งจะไม่บันทึกข้อมูลและพาผู้ใช้กลับสู่หน้าก่อนหน้า (หรือกลับหน้าหลัก `/` หากไม่มีประวัติหน้าก่อนหน้า) <- UC-10 main flow ขั้น 5, alternative 5a
- FR-REP-04: ระบบต้องตรวจสอบความถูกต้องและครบถ้วนของข้อมูลบังคับกรอก (ประเภทปัญหา และรายละเอียดปัญหา) เมื่อกรอกหรือกดยืนยัน หากข้อมูลไม่ครบถ้วนหรือเกินความยาวที่กำหนดให้ไม่อนุญาตให้บันทึกและแสดงข้อความแจ้งเตือนใต้ช่องข้อมูลที่เกี่ยวข้อง <- UC-10 main flow ขั้น 6, exception 6a
- FR-REP-05: ระบบต้องตรวจสอบไฟล์รูปภาพที่อัปโหลด (รองรับเฉพาะ `.jpg`, `.jpeg`, `.png` ขนาดไม่เกิน 5MB ต่อไฟล์ และไม่เกิน 3 ไฟล์) หากไฟล์ไม่ถูกต้องหรือเกิดข้อผิดพลาดขณะอัปโหลด/บันทึกข้อมูล ระบบต้องแจ้งเตือนให้เลือกไฟล์ใหม่และไม่บันทึกข้อมูลค้างบางส่วน <- UC-10 exception 6b
- FR-REP-06: ระบบต้องบันทึกข้อมูลการแจ้งซ่อมและรูปภาพลงฐานข้อมูลภายใต้ Transaction เดียวกัน แจ้งเตือนความสำเร็จบนหน้าจอ และแสดงรายการแจ้งซ่อมพร้อมสถานะเริ่มต้น "รอดำเนินการ" (`Pending`) ให้ผู้ใช้ทราบ <- UC-10 main flow ขั้น 7-8

## Quality Requirements
- NFR-PERF-01: วัดตั้งแต่ผู้ใช้กดยืนยันการแจ้งซ่อม ระบบต้องบันทึกข้อมูลและตอบสนองความสำเร็จด้วยค่า p95 <= 2 วินาทีในสภาวะเครือข่ายปกติ
- NFR-USE-01: แบบฟอร์มแจ้งซ่อมต้องมีป้ายกำกับ (Label) ครบทุกช่อง กรอกและส่งรายการได้ภายใน 1 หน้าจอ และแสดงข้อความผิดพลาดใต้ช่องที่เกี่ยวข้องทันทีเมื่อข้อมูลไม่ถูกต้อง
- NFR-SEC-01: ข้อมูลและรูปภาพที่แนบมาต้องรับส่งผ่าน HTTPS (ในสภาพแวดล้อมจริง) จัดเก็บไฟล์ภาพในโฟลเดอร์เซิร์ฟเวอร์แบบไม่เปิดสาธารณะ (Non-public) และจำกัดสิทธิ์การเข้าถึงรูปภาพเฉพาะ Resident ผู้แจ้งรายการนั้น, เจ้าของหอพักของหอนั้น และ Admin เท่านั้น

## Acceptance Criteria
- [ ] AC-REP-01 (FR-REP-01, FR-REP-04, FR-REP-06, CON-SYS-01, CON-UI-01)
      Given ผู้ใช้ที่เป็น Resident เข้าสู่หน้าแจ้งซ่อม (รองรับทั้งหน้าจอ 375px, 768px, 1280px) เลือกประเภทปัญหาและกรอกรายละเอียดครบถ้วน
      When  ผู้ใช้กดยืนยันการแจ้งซ่อม
      Then  ระบบบันทึกข้อมูลสำเร็จ แจ้งเตือนผู้ใช้ แสดงสถานะรายการซ่อมเป็น "รอดำเนินการ" (`Pending`) และข้อมูลถูกอ้างอิงกับ `resident_id` และ `room_id` ของผู้ใช้อย่างถูกต้อง
- [ ] AC-REP-02 (FR-REP-02, FR-REP-05, NFR-SEC-01)
      Given ผู้ใช้กรอกข้อมูลครบถ้วนและแนบไฟล์ภาพที่มีขนาด/รูปแบบตามที่กำหนด (`.jpg`, `.jpeg`, `.png` ขนาดไม่เกิน 5MB ต่อไฟล์ สูงสุด 3 ไฟล์)
      When  ผู้ใช้กดยืนยันการแจ้งซ่อม
      Then  ระบบบันทึกข้อมูลและอัปโหลดไฟล์สำเร็จ เก็บอ้างอิงไฟล์ภาพอย่างปลอดภัยโดยไม่เปิดสาธารณะ และปฏิเสธการเข้าถึงรูปภาพจากผู้ใช้ที่ไม่มีสิทธิ์
- [ ] AC-REP-03 (FR-REP-04, NFR-USE-01)
      Given ผู้ใช้เว้นว่างข้อมูลที่จำเป็น (ไม่เลือกประเภทปัญหา หรือไม่กรอกรายละเอียดปัญหา)
      When  ผู้ใช้กดยืนยันการแจ้งซ่อม
      Then  ระบบไม่อนุญาตให้บันทึก และแสดงข้อความแจ้งเตือนใต้ช่องข้อมูลที่ผิดพลาดนั้น
- [ ] AC-REP-04 (FR-REP-05)
      Given ผู้ใช้อัปโหลดรูปภาพผิดประเภท (เช่น `.pdf`), ขนาดเกิน 5MB, จำนวนเกิน 3 ไฟล์ หรือจำลองกรณีบันทึกข้อมูล/ไฟล์ไม่สำเร็จ
      When  ผู้ใช้อัปโหลดไฟล์หรือกดยืนยันการแจ้งซ่อม
      Then  ระบบแสดงข้อความแจ้งเตือนให้เลือกไฟล์ใหม่หรือแจ้งข้อผิดพลาด และไม่อนุญาตให้บันทึกข้อมูลค้างบางส่วน
- [ ] AC-REP-05 (FR-REP-03)
      Given ผู้ใช้กำลังกรอกฟอร์มแจ้งซ่อม
      When  ผู้ใช้กดปุ่ม "ยกเลิก"
      Then  ระบบไม่บันทึกข้อมูล และนำผู้ใช้กลับไปยังหน้าก่อนหน้าทันที (หรือหน้าหลัก `/` หากไม่มีหน้าก่อนหน้า)
- [ ] AC-REP-06 (NFR-PERF-01)
      Given ข้อมูลในแบบฟอร์มและการอัปโหลดถูกต้อง
      When  ระบบดำเนินการตรวจสอบและบันทึกข้อมูล
      Then  เวลาตอบสนองของระบบต้องเสร็จสิ้นด้วยค่า p95 <= 2 วินาที

## Assumptions & Open Questions

### Assumptions
- ASM-01: ผู้ใช้งานต้องมีข้อมูลระบุตัวตนที่บอกว่าพักอยู่ห้องใด ระบบจะดึง `resident_id` และ `room_id` อัตโนมัติจากข้อมูลผู้ใช้ฝั่งเซิร์ฟเวอร์ โดยไม่รับค่า `room_id` จากฟอร์มฝั่ง Client เพื่อป้องกันการแอบอ้างห้องอื่น
- ASM-02: รูปแบบสถานะเริ่มต้นของการแจ้งซ่อมเมื่อบันทึกสำเร็จคือ "รอดำเนินการ" (`Pending`)
- ASM-03: ประเภทไฟล์ภาพที่รองรับคือ `.jpg`, `.jpeg`, `.png` ขนาดไฟล์สูงสุดไม่เกิน 5MB ต่อไฟล์ และแนบได้สูงสุด 3 ไฟล์ต่อ 1 รายการแจ้งซ่อม (การแนบรูปภาพเป็น Optional)
- ASM-04: รหัส ID `SPEC-REP-010` ถือเป็นรหัสที่ทีมตกลงใช้งานเพื่ออ้างอิงสำหรับฟีเจอร์นี้
- ASM-05: ระหว่างที่ระบบเข้าสู่ระบบกลาง (`UC-07`) ยังไม่มีการพัฒนาใน Repository ระบบจะรับตัวตนผู้พักอาศัยผ่าน HTTP Header จำลอง `X-Resident-Id` และตรวจสอบว่าผู้ใช้นั้นมีสิทธิ์พักอาศัยในห้องจริง หากไม่มี Header หรือไม่พบสิทธิ์ให้ปฏิเสธคำขอ (`401`/`403`)
- ASM-06: รายการตัวเลือก "ประเภทปัญหา" ในแบบฟอร์มประกอบด้วย 4 หมวด ได้แก่ `ไฟฟ้า`, `ประปา`, `เฟอร์นิเจอร์/อุปกรณ์` และ `อื่นๆ` โดยบังคับเลือกประเภทปัญหาและกรอกรายละเอียดปัญหา (1–1,000 ตัวอักษร)
- ASM-07: หลังบันทึกแจ้งซ่อมสำเร็จ ระบบจะแสดงข้อความแจ้งเตือนบนหน้าจอ และแสดงรายการประวัติการแจ้งซ่อมพร้อมสถานะล่าสุดของห้องพักผู้ใช้อยู่ด้านล่างแบบฟอร์มในหน้า `/repairs/new` ทันที
- ASM-08: การบันทึกข้อมูลการแจ้งซ่อมและข้อมูลรูปภาพต้องทำงานภายใต้ Database Transaction เดียวกัน หากการบันทึกไฟล์หรือฐานข้อมูลส่วนใดล้มเหลวต้อง Rollback ทั้งหมดและลบไฟล์ที่ค้างอยู่

### Open Questions
- ไม่มีในขอบเขตของ UC-10 ณ เวอร์ชันนี้
