# Feature: เข้าสู่ระบบ (Login)

Spec ID: SPEC-LOGIN-001 | Source: UC-07 | Use case: UC-07

Owner: ทีมพัฒนาระบบ | Status: Draft v2 | Updated: 2569-09-20

## Goal

ผู้ใช้งานที่มีบัญชีในระบบสามารถเข้าสู่ระบบด้วยชื่อผู้ใช้หรืออีเมลและรหัสผ่านได้อย่างปลอดภัย ระบบต้องตรวจสอบข้อมูลบัญชี สถานะบัญชี และกำหนดสิทธิ์ตามบทบาทของผู้ใช้ พร้อมนำผู้ใช้ไปยังหน้าที่เหมาะสมภายใน 2 วินาทีภายใต้สภาวะการใช้งานปกติ

## Scope

### In scope

- เข้าสู่ระบบด้วยชื่อผู้ใช้หรืออีเมลและรหัสผ่าน
- ตรวจสอบข้อมูลบัญชีก่อนอนุญาตให้เข้าสู่ระบบ
- ตรวจสอบสถานะบัญชีว่าใช้งานได้หรือถูกระงับ
- สร้าง session เมื่อเข้าสู่ระบบสำเร็จ
- กำหนดสิทธิ์ตาม role ของผู้ใช้
- นำผู้ใช้ไปยังหน้าที่เหมาะสมตาม role
- แสดงข้อความแจ้งเตือนเมื่อเข้าสู่ระบบไม่สำเร็จ
- รองรับลิงก์สมัครสมาชิกและลืมรหัสผ่าน
- ป้องกันการเข้าถึงฟังก์ชันที่ต้อง Login โดยไม่มี session

### Out of scope

- การสมัครสมาชิกโดยละเอียด (UC-02)
- การจัดการข้อมูลบัญชีผู้ใช้ (UC-08)
- การรีเซ็ตรหัสผ่านโดยละเอียด
- การจัดการสิทธิ์เชิงลึกของแต่ละฟังก์ชันหลังจากเข้าสู่ระบบ

## Constraints

- CON-ACC-01 ผู้ใช้ต้องมีบัญชีที่ลงทะเบียนไว้ก่อนจึงจะเข้าสู่ระบบได้
- CON-LOGIN-01 ระบบต้องตรวจสอบข้อมูลบัญชีก่อนสร้าง session
- CON-LOGIN-02 บัญชีที่ถูกระงับต้องไม่สามารถเข้าสู่ระบบและสร้าง session ได้
- CON-LOGIN-03 สิทธิ์การเข้าถึงหลังเข้าสู่ระบบต้องอ้างอิงจาก role ของบัญชี
- CON-SEC-01 รหัสผ่านต้องไม่ถูกจัดเก็บเป็น plain text
- CON-SEC-02 การรับส่งข้อมูล Login ต้องดำเนินการผ่าน HTTPS/TLS
- CON-UI-01 หน้า Login ต้องรองรับการใช้งานบนอุปกรณ์ที่ระบบรองรับ

## Requirements

- FR-LOGIN-01 ระบบต้องให้ผู้ใช้เข้าสู่ระบบด้วยชื่อผู้ใช้หรืออีเมลและรหัสผ่าน
  <- UC-07 main flow ขั้น 1-4

- FR-LOGIN-02 ระบบต้องตรวจสอบว่าข้อมูลบัญชีและรหัสผ่านถูกต้องก่อนอนุญาตให้เข้าสู่ระบบ
  <- UC-07 main flow ขั้น 5, 7

- FR-LOGIN-03 ระบบต้องตรวจสอบสถานะบัญชีก่อนสร้าง session และต้องปฏิเสธบัญชีที่ถูกระงับ
  <- UC-07 main flow ขั้น 6, exception 5b

- FR-LOGIN-04 เมื่อเข้าสู่ระบบสำเร็จ ระบบต้องสร้าง session และบันทึกสถานะการเข้าสู่ระบบของผู้ใช้
  <- UC-07 main flow ขั้น 7

- FR-LOGIN-05 ระบบต้องกำหนดสิทธิ์และนำผู้ใช้ไปยังหน้าที่เหมาะสมตาม role ได้แก่ Guest, Resident, Dormitory Owner และ Admin
  <- UC-07 main flow ขั้น 8

- FR-LOGIN-06 หากชื่อผู้ใช้/อีเมลหรือรหัสผ่านไม่ถูกต้อง ระบบต้องแสดงข้อความแจ้งเตือนโดยไม่ระบุว่าข้อมูลส่วนใดผิด
  <- UC-07 exception 5a

- FR-LOGIN-07 หากผู้ใช้ไม่มีบัญชี ระบบต้องมีช่องทางนำไปยัง flow สมัครสมาชิก
  <- UC-07 alternative 2a

- FR-LOGIN-08 หากผู้ใช้ลืมรหัสผ่าน ระบบต้องมีช่องทางนำไปยัง flow สำหรับรีเซ็ตรหัสผ่าน
  <- UC-07 alternative 3a

- FR-LOGIN-09 ผู้ใช้ที่ไม่มี session ต้องไม่สามารถเข้าถึงฟังก์ชันที่กำหนดให้เฉพาะผู้ที่เข้าสู่ระบบแล้ว
  <- UC-07 postcondition / authentication requirement

## Quality Requirements

- NFR-USE-01 หน้า Login ต้องใช้งานง่าย มีช่อง username/email, password, ปุ่ม Login และช่องทางสมัครสมาชิก/ลืมรหัสผ่านอย่างชัดเจน

- NFR-PERF-01 การตรวจสอบ Login และการตอบสนองของระบบต้องเสร็จสิ้นภายใน 2 วินาทีภายใต้สภาวะเครือข่ายปกติ

- NFR-SEC-01 รหัสผ่านต้องไม่ถูกจัดเก็บเป็น plain text และต้องได้รับการปกป้องอย่างเหมาะสม

- NFR-SEC-02 ข้อมูล Login ที่รับส่งระหว่าง Browser และระบบต้องเข้ารหัสผ่าน HTTPS/TLS 1.2 ขึ้นไป

- NFR-SEC-03 ระบบต้องไม่เปิดเผยข้อมูลที่ช่วยระบุว่าชื่อผู้ใช้/อีเมลหรือรหัสผ่านเป็นข้อมูลที่ผิด

## Acceptance Criteria

- [ ] AC-LOGIN-01 (FR-LOGIN-01, FR-LOGIN-02, FR-LOGIN-04)

      Given ผู้ใช้มีบัญชีที่สามารถใช้งานได้

      When ผู้ใช้กรอก username/email และ password ที่ถูกต้องแล้วกด Login

      Then ระบบตรวจสอบข้อมูลสำเร็จ สร้าง session และให้ผู้ใช้เข้าสู่ระบบได้

- [ ] AC-LOGIN-02 (FR-LOGIN-05)

      Given ผู้ใช้เข้าสู่ระบบสำเร็จและมี role ที่กำหนดไว้

      When ระบบตรวจสอบ role ของผู้ใช้

      Then ระบบนำผู้ใช้ไปยังหน้าที่ตรงกับสิทธิ์ของ role นั้น

- [ ] AC-LOGIN-03 (FR-LOGIN-06)

      Given ผู้ใช้กรอก username/email หรือ password ไม่ถูกต้อง

      When ผู้ใช้กด Login

      Then ระบบไม่สร้าง session และแสดงข้อความแจ้งเตือนโดยไม่ระบุว่าข้อมูลส่วนใดผิด

- [ ] AC-LOGIN-04 (FR-LOGIN-03)

      Given บัญชีผู้ใช้มีสถานะถูกระงับ

      When ผู้ใช้พยายาม Login ด้วยข้อมูลบัญชีดังกล่าว

      Then ระบบไม่อนุญาตให้เข้าสู่ระบบและไม่สร้าง session

- [ ] AC-LOGIN-05 (FR-LOGIN-07)

      Given ผู้ใช้ยังไม่มีบัญชี

      When ผู้ใช้เลือกช่องทางสมัครสมาชิก

      Then ระบบนำผู้ใช้ไปยัง flow สมัครสมาชิกที่กำหนดไว้

- [ ] AC-LOGIN-06 (FR-LOGIN-08)

      Given ผู้ใช้จำรหัสผ่านไม่ได้

      When ผู้ใช้เลือก "ลืมรหัสผ่าน"

      Then ระบบนำผู้ใช้ไปยัง flow สำหรับรีเซ็ตรหัสผ่าน

- [ ] AC-LOGIN-07 (FR-LOGIN-09)

      Given ผู้ใช้ยังไม่มี session

      When ผู้ใช้พยายามเข้าถึงฟังก์ชันที่ต้องเข้าสู่ระบบ

      Then ระบบไม่อนุญาตให้เข้าถึง และนำผู้ใช้ไปยังหน้า Login

- [ ] AC-LOGIN-08 (NFR-PERF-01)

      Given ระบบอยู่ในสภาวะการใช้งานปกติ

      When ผู้ใช้ส่งคำขอ Login

      Then ระบบตอบสนองภายใน 2 วินาที

## Assumptions & Open Questions

- ASM-01 ผู้ใช้ต้องมีบัญชีที่ลงทะเบียนไว้ก่อนเข้าสู่ระบบ

- ASM-02 แต่ละบัญชีมี role ที่กำหนดไว้ในระบบ ได้แก่ Guest, Resident, Dormitory Owner หรือ Admin

- ASM-03 ระบบมีวิธีจัดการ session หลัง authentication สำเร็จ

- ASM-04 การสมัครสมาชิกเป็น flow ที่แยกออกจาก UC-07 และอ้างอิง UC-02

- ASM-05 การจัดการข้อมูลบัญชีผู้ใช้อ้างอิง UC-08

- ASM-06 รายละเอียดของการรีเซ็ตรหัสผ่านจะกำหนดใน flow หรือ Use Case ที่เกี่ยวข้อง
