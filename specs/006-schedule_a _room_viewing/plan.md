# แผนทางเทคนิค: นัดหมายดูห้องพัก (Schedule a Room Viewing)

อ้างอิง: `specs/006-Schedule_a Room_Viewing/spec.md`  
Spec ID: `SPEC-APPT-001` | Status: `Draft v2`

## 1. สรุปแนวทาง

1. สร้างหน้าฟอร์มนัดหมายดูห้องพักในหน้ารายละเอียดหอพักตาม `FR-APPT-01` และ `CON-UI-01` พร้อมให้ผู้เช่าเลือกวันที่และช่วงเวลาที่ว่างในหน้าเดียว
2. ดึงข้อมูลช่วงเวลาว่างของหอพักตามวันที่ที่เลือก พร้อมคำนวณช่วงที่สามารถนัดหมายได้ตามเงื่อนไขวันจันทร์–เสาร์ เวลา 09:00–18:00 น. และระยะเวลา 30 นาทีต่อรอบ เพื่อให้ผู้ใช้เห็นเฉพาะช่วงที่ว่างและป้องกันการเลือกช่วงที่ถูกจองหรือไม่อยู่ในช่วงที่อนุญาตตาม `FR-APPT-02`, `FR-APPT-04`, `FR-APPT-05`, `FR-APPT-07`, `ASM-08`, `ASM-09`
3. สร้างบริการตรวจสอบความถูกต้องและความซ้ำของการนัดหมายก่อนบันทึก โดยตรวจสอบวันที่/เวลา, วันอาทิตย์, ช่วงเวลาทำการ, และการทับซ้อนของช่วงเวลากับคำขอที่มีอยู่ในหอพักเดียวกันตาม `FR-APPT-05`, `FR-APPT-06`, `CON-TIME-01`, `CON-TIME-02`
4. บันทึกคำขอนัดหมายหลังจากผู้ใช้ยืนยันการส่งคำขอ และพยายามส่งข้อความแจ้งเตือนไปยังเจ้าของหอพักตาม `FR-APPT-08`, `FR-APPT-09`, `FR-APPT-10`, `ASM-04`, `ASM-05` หากการแจ้งเตือนไม่สำเร็จ ระบบจะยังคงบันทึก `Appointment` ไว้และแสดงข้อความแจ้งให้ผู้ใช้ทราบว่าการแจ้งเตือนไม่สำเร็จ
5. รักษา flow การยกเลิกก่อนยืนยัน โดยเมื่อยกเลิกให้กลับไปยังหน้ารายละเอียดหอพัก และเมื่อส่งคำขอสำเร็จให้แสดงข้อความยืนยันพร้อมรายละเอียดวันและเวลานัดหมายตาม `FR-APPT-11`, `AC-APPT-05`, `AC-APPT-06` พร้อมตรวจสอบให้ระบบตรวจสอบและบันทึกคำขอนัดหมายภายใน 3 วินาทีตาม `NFR-PERF-01`

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Appointment` | `appointment_id`, `resident_id`, `dormitory_id`, `viewing_date`, `start_time`, `end_time`, `created_at`, `notification_status` | `FR-APPT-03`, `FR-APPT-08`, `FR-APPT-09`, `FR-APPT-10`, `FR-APPT-11`, `ASM-04`, `ASM-08` |

กติกาข้อมูล:

- ไม่เก็บข้อมูลใดที่อยู่นอกขอบเขต เช่น การจัดการบัญชีผู้ใช้ การอนุมัติการนัดหมาย หรือการจัดการข้อมูลหอพักตาม Out of scope
- ช่วงเวลาที่ว่างจะคำนวณแบบรวมจากข้อมูล `Appointment` ที่มีอยู่และช่วงเวลาทำการที่อนุญาตในแต่ละวัน โดยใช้กติกาให้สามารถนัดหมายได้เฉพาะวันจันทร์–เสาร์ เวลา 09:00–18:00 และแต่ละช่วงมีระยะเวลา 30 นาทีตาม `ASM-02`, `ASM-03`, `ASM-08`, `ASM-09`
- การตรวจการทับซ้อนจะทำแบบช่วงเวลาในหอพักเดียวกันเท่านั้น ตาม `ASM-07`
- `FR-APPT-11` ให้ frontend ทำการยกเลิกข้อมูลในฟอร์มและกลับไปยังหน้ารายละเอียดหอพักทันที โดยไม่ส่งข้อมูลไปยัง backend เนื่องจากผู้ใช้ยังไม่ได้ยืนยันการส่งคำขอ
- หากการส่งสัญญาณแจ้งเตือนไปยังเจ้าของหอพักไม่สำเร็จ ระบบจะไม่ยกเลิกการบันทึก `Appointment` และจะต้องแจ้งกลับไปยังผู้ใช้ว่าการแจ้งเตือนไม่สำเร็จ ตาม `FR-APPT-09`

## 4. API / หน้าจอ

- `GET /dormitories/{id}/viewing-slots?date=YYYY-MM-DD` — ดึงช่วงเวลาว่างสำหรับวันที่เลือก โดยกรองเฉพาะช่วงที่อยู่ภายในวันจันทร์–เสาร์ เวลา 09:00–18:00 และมีขนาด 30 นาทีต่อรอบตาม `FR-APPT-02`, `FR-APPT-04`, `FR-APPT-05`, `ASM-08`, `ASM-09`
- `POST /api/appointments` — รับข้อมูล `dormitory_id`, `viewing_date`, `start_time`, `end_time`, `resident_id`; validate; ตรวจซ้ำ; บันทึกคำขอเมื่อผ่านทุกเงื่อนไข และพยายามส่งการแจ้งเตือนไปยังเจ้าของหอพักตาม `FR-APPT-03`, `FR-APPT-05`, `FR-APPT-06`, `FR-APPT-08`, `FR-APPT-09`
- หน้า `/dormitory/{id}` — แสดงเมนูนัดหมายและฟอร์มในหน้าเดียว พร้อมปฏิทินและช่วงเวลาว่างตาม `FR-APPT-01`, `FR-APPT-02`, `CON-UI-01` และ `FR-APPT-11` ให้ frontend ยกเลิกข้อมูลในฟอร์มและกลับไปหน้ารายละเอียดหอพักโดยไม่ส่งข้อมูลไป backend
- หน้า `/dormitory/{id}/appointment-success` — แสดงข้อความยืนยันพร้อมรายละเอียดวันและเวลาและนำกลับไปหน้ารายละเอียดหอพักตาม `FR-APPT-10`, `AC-APPT-05`

## 7. ลำดับงาน

1. สร้างโครงหน้า `/dormitory/{id}` และฟอร์มเลือกวันเวลาแบบหน้าเดียวตาม `FR-APPT-01`, `FR-APPT-02`, `CON-UI-01`
2. สร้าง API ดึงช่วงเวลาว่างตามวันที่ที่เลือก พร้อม filter เฉพาะช่วงที่สามารถเลือกได้ภายในวันจันทร์–เสาร์ เวลา 09:00–18:00 และทั้งช่วงมีขนาด 30 นาทีตาม `FR-APPT-02`, `FR-APPT-04`, `FR-APPT-05`, `ASM-08`, `ASM-09`
3. เพิ่ม validation สำหรับวันที่และเวลา เช่น วันที่ไม่เป็นอดีตและไม่ใช่วันอาทิตย์, ช่วงเวลาภายในช่วงนัดหมายที่อนุญาต, และเลือกได้เพียงหนึ่งช่วงต่อหนึ่งคำขอตาม `FR-APPT-03`, `FR-APPT-05`, `FR-APPT-07`, `ASM-10`
4. เพิ่ม logic ตรวจการทับซ้อนของช่วงเวลาในหอพักเดียวกันก่อนบันทึกคำขอและป้องกันคำขอซ้ำตาม `FR-APPT-06`, `CON-TIME-01`, `ASM-07`
5. สร้าง `POST /api/appointments` สำหรับบันทึกคำขอ และพยายามส่ง Notification ให้เจ้าของหอพักตาม `FR-APPT-08`, `FR-APPT-09`, `ASM-05` หากส่งไม่สำเร็จให้ยังคงบันทึก `Appointment` ไว้และแจ้งผู้ใช้ว่าการแจ้งเตือนไม่สำเร็จ
6. เพิ่มหน้าแสดงข้อความยืนยันหลังส่งคำขอสำเร็จ และเพิ่มการยกเลิกข้อมูลในฟอร์มก่อนยืนยันโดยไม่ส่งข้อมูลไป backend ตาม `FR-APPT-10`, `FR-APPT-11`, `AC-APPT-05`, `AC-APPT-06`
7. ทดสอบครบตาม `AC-APPT-01` ถึง `AC-APPT-06` และทดสอบความเร็ว Response ตาม `NFR-PERF-01`
