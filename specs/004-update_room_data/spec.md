# Feature: อัปเดตสถานะห้องว่าง (Room Availability Status Update)

Spec ID: SPEC-DOR-004 | Source: ข้อกำหนดความต้องการข้อ 3-4 | Use case: UC-04

Owner: ทีมพัฒนาระบบหอพัก | Status: Draft v2 | Updated: 2569-09-20

## Goal

เจ้าของหอพักสามารถอัปเดตสถานะห้องพักระหว่าง "ห้องว่าง" และ "ห้องเต็ม" ได้อย่างสะดวกและรวดเร็ว เพื่อให้ผู้สนใจเช่าเห็นสถานะห้องพักที่เป็นปัจจุบันและตรงกับความเป็นจริง

## Scope

### In scope

* แสดงรายการห้องพักของหอพักที่เจ้าของหอพักเป็นผู้ดูแล
* แสดงสถานะปัจจุบันของแต่ละห้องพัก
* เปลี่ยนสถานะห้องพักเป็น "ห้องว่าง" หรือ "ห้องเต็ม"
* เปลี่ยนสถานะของหลายห้องพร้อมกัน
* ยืนยันการเปลี่ยนแปลงสถานะ
* บันทึกสถานะใหม่ลงในฐานข้อมูล
* แสดงสถานะใหม่หลังจากบันทึกสำเร็จ
* ให้ผู้ใช้งานทั่วไปเห็นสถานะห้องพักที่อัปเดตล่าสุด

### Out of scope

* การเพิ่มหรือแก้ไขรายละเอียดห้องพัก ราคา และข้อมูลหอพักอื่น ๆ (UC-03)
* การค้นหาและดูข้อมูลหอพักของผู้ใช้งานทั่วไป (UC-01)
* การนัดหมายเพื่อดูห้องพัก (UC-06)
* การจองห้องพัก (UC-12)
* การตรวจสอบและอนุมัติหอพักโดย Admin (UC-13)

## Constraints

* CON-AUTH-01 เจ้าของหอพักต้องเข้าสู่ระบบก่อนจึงสามารถอัปเดตสถานะห้องพักได้
* CON-AUTH-02 เจ้าของหอพักที่เข้าสู่ระบบ และผู้ที่ได้รับมอบหมายจากเจ้าของหอพักเท่านั้น ที่สามารถเปลี่ยนสถานะห้องพักของหอพักที่ตนเองรับผิดชอบได้
* CON-STATUS-01 สถานะห้องพักที่ระบบรองรับใน UC-04 คือ "ห้องว่าง" และ "ห้องเต็ม" เท่านั้น
* CON-DATA-01 ระบบต้องบันทึกสถานะใหม่ลงในฐานข้อมูลก่อนแสดงสถานะดังกล่าวเป็นสถานะปัจจุบัน
* CON-SYNC-01 เมื่ออัปเดตสถานะสำเร็จ ระบบต้องเผยแพร่สถานะล่าสุดไปยังหน้าค้นหาและรายละเอียดหอพักของผู้ใช้งานทั่วไปภายใน 2 วินาที หาก Sync ล้มเหลว ระบบต้องแจ้งเตือนและให้เจ้าของหอพักสามารถ Retry ได้

## Requirements

* FR-DOR-19 ระบบต้องแสดงรายการห้องพักทั้งหมดของเจ้าของหอพัก พร้อมสถานะปัจจุบันของแต่ละห้อง
* FR-DOR-20 ระบบต้องให้เจ้าของหอพักสามารถเปลี่ยนสถานะห้องพักระหว่าง "ห้องว่าง" และ "ห้องเต็ม" ได้ (Req #4)
* FR-DOR-21 ระบบต้องให้เจ้าของหอพักสามารถเลือกเปลี่ยนสถานะห้องพักหลายห้องพร้อมกันได้ โดยยืนยันและบันทึกสถานะพร้อมกันในครั้งเดียว
* FR-DOR-22 ระบบต้องให้เจ้าของหอพักยืนยันการเปลี่ยนแปลงก่อนบันทึกสถานะใหม่
* FR-DOR-23 เมื่อเจ้าของหอพักยืนยัน ระบบต้องบันทึกสถานะห้องพักใหม่ลงในฐานข้อมูล
* FR-DOR-24 เมื่อบันทึกสำเร็จ ระบบต้องแสดงข้อความแจ้งเตือนการอัปเดตสถานะสำเร็จ
* FR-DOR-25 ระบบต้องแสดงสถานะห้องพักล่าสุดหลังจากบันทึกสำเร็จทันที
* FR-DOR-26 ระบบต้องแสดงสถานะห้องพักที่อัปเดตล่าสุดแก่ผู้ใช้งานทั่วไปในหน้าค้นหาและหน้ารายละเอียดหอพักเมื่อผู้ใช้งานทั่วไปเปิดหรือ Refresh หน้า โดยไม่ต้องรองรับ Real-time Update (Req #3)
* FR-DOR-27 หากเจ้าของหอพักยกเลิกการเปลี่ยนแปลง หรือเกิดข้อผิดพลาดระหว่างบันทึก ระบบต้องไม่บันทึกการเปลี่ยนแปลงของห้องที่เลือกไว้ทั้งหมด และคงสถานะเดิมของห้องทุกห้องที่เลือกไว้
* FR-DOR-28 หากไม่สามารถบันทึกสถานะใหม่ได้ ระบบต้องแจ้งเตือนความผิดพลาดและคงสถานะเดิมไว้ พร้อมให้เจ้าของหอพัก Retry ได้

## Quality Requirements

* NFR-PERF-02 การอัปเดตและแสดงผลสถานะห้องพักใหม่ต้องเสร็จสิ้นภายใน 2 วินาที ภายใต้สภาวะเครือข่ายปกติ
* NFR-USE-03 ปุ่มหรือส่วนควบคุมสำหรับเปลี่ยนสถานะห้องพักต้องมองเห็นได้ชัดเจนและใช้งานง่าย
* NFR-DATA-03 สถานะห้องพักที่แสดงแก่ผู้ใช้งานทั่วไปต้องตรงกับสถานะล่าสุดที่บันทึกในฐานข้อมูล
* NFR-SEC-03 ระบบต้องป้องกันไม่ให้เจ้าของหอพักแก้ไขสถานะห้องพักของเจ้าของหอพักรายอื่น

## Acceptance Criteria

* [ ] AC-DOR-13 (FR-DOR-19, FR-DOR-20)

  ```
  Given เจ้าของหอพักเข้าสู่ระบบและมีห้องพักอยู่ในระบบ

  When เจ้าของหอพักเลือกห้องพักและเปลี่ยนสถานะเป็น "ห้องว่าง" หรือ "ห้องเต็ม"

  Then ระบบสามารถเปลี่ยนสถานะห้องพักตามที่เจ้าของหอพักเลือกได้
  ```

* [ ] AC-DOR-14 (FR-DOR-21)

  ```
  Given เจ้าของหอพักมีห้องพักหลายห้องที่ต้องการเปลี่ยนสถานะ

  When เจ้าของหอพักเลือกหลายห้องและกำหนดสถานะใหม่แล้วกดยืนยันครั้งเดียว

  Then ระบบสามารถเปลี่ยนสถานะของห้องพักที่เลือกพร้อมกันได้ในครั้งเดียว
  ```

* [ ] AC-DOR-15 (FR-DOR-23, FR-DOR-24, FR-DOR-25)

  ```
  Given เจ้าของหอพักเลือกสถานะใหม่และยืนยันการเปลี่ยนแปลง

  When ระบบบันทึกสถานะลงฐานข้อมูลสำเร็จ

  Then ระบบแสดงข้อความแจ้งเตือนการอัปเดตสำเร็จ และแสดงสถานะใหม่ทันที
  ```

* [ ] AC-DOR-16 (FR-DOR-26)

  ```
  Given เจ้าของหอพักอัปเดตสถานะห้องพักสำเร็จ

  When ผู้ใช้งานทั่วไปเปิดหรือ Refresh หน้าค้นหา/รายละเอียดหอพัก

  Then ระบบแสดงสถานะห้องพักล่าสุดตรงตามสถานะที่เจ้าของหอพักอัปเดต
  ```

* [ ] AC-DOR-17 (FR-DOR-27)

  ```
  Given เจ้าของหอพักกำลังเปลี่ยนสถานะห้องพักหลายห้องพร้อมกัน

  When เจ้าของหอพักกดปุ่ม "ยกเลิก" หรือเกิดข้อผิดพลาดระหว่างบันทึก

  Then ระบบไม่บันทึกการเปลี่ยนแปลงของห้องทั้งหมดที่เลือกไว้ และคงสถานะเดิมของห้องทุกห้องที่เลือกไว้
  ```

* [ ] AC-DOR-18 (FR-DOR-28)

  ```
  Given เกิดข้อผิดพลาดระหว่างบันทึกสถานะห้องพัก

  When ระบบไม่สามารถบันทึกสถานะใหม่ลงฐานข้อมูลได้

  Then ระบบแสดงข้อความ "ไม่สามารถบันทึกสถานะได้" คงสถานะเดิมไว้ และให้เจ้าของหอพักสามารถ Retry ได้
  ```

* [ ] AC-DOR-19 (NFR-PERF-02)

  ```
  Given เจ้าของหอพักเปลี่ยนสถานะห้องพัก

  When ระบบบันทึกและอัปเดตการแสดงผลสถานะ

  Then การอัปเดตและแสดงผลสถานะใหม่ต้องเสร็จสิ้นภายใน 2 วินาทีภายใต้สภาวะเครือข่ายปกติ
  ```

## Assumptions & Open Questions

* ASM-11 เจ้าของหอพักมีบัญชีผู้ใช้งานและผ่านการยืนยันตัวตนก่อนใช้งาน UC-04
* ASM-12 ข้อมูลห้องพักของเจ้าของหอพักถูกสร้างและจัดการผ่าน UC-03
* ASM-13 สถานะห้องพักมีเพียง "ห้องว่าง" และ "ห้องเต็ม" สำหรับการใช้งานใน UC-04 เท่านั้น
* ASM-14 การเปลี่ยนสถานะหอพักมีผลต่อสถานะที่แสดงในหน้าค้นหาและหน้ารายละเอียดของผู้ใช้งานทั่วไปเมื่อเปิดหรือ Refresh หน้า
* ASM-15 หากเกิดข้อผิดพลาดระหว่างบันทึก ระบบจะไม่เปลี่ยนสถานะในฐานข้อมูลเป็นสถานะใหม่ และคงสถานะเดิมของห้องทั้งหมดที่เลือกไว้
* ASM-16 ผู้ที่มีสิทธิ์จัดการคือเจ้าของหอพักที่เข้าสู่ระบบ และผู้ที่ได้รับมอบหมายจากเจ้าของหอพักเท่านั้น
* ASM-17 การเปลี่ยนสถานะหลายห้องพร้อมกันจะยืนยันและบันทึกในครั้งเดียว เพื่อให้คงความสอดคล้องของข้อมูลใน batch นั้น
