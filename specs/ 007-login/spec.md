# Feature: เข้าสู่ระบบ (Login)

Spec ID: SPEC-LOGIN-001 | Source: UC-07 | Use case: UC-07  
Owner: ทีมพัฒนาระบบหอพัก | Status: Draft v1 | Updated: 2569-09-20

## Goal

ผู้ใช้งานสามารถเข้าสู่ระบบด้วยข้อมูลบัญชีของตนเองได้อย่างปลอดภัย
และได้รับสิทธิ์การใช้งานตามบทบาทของบัญชี ได้แก่ Guest, Resident,
Dormitory Owner และ Admin

## Scope

### In scope

- เข้าสู่ระบบด้วยชื่อผู้ใช้หรืออีเมลและรหัสผ่าน
- ตรวจสอบข้อมูลบัญชีและรหัสผ่าน
- ตรวจสอบสถานะของบัญชีก่อนอนุญาตให้เข้าสู่ระบบ
- กำหนดสิทธิ์ตามบทบาทของผู้ใช้
- สร้าง session หลังจากเข้าสู่ระบบสำเร็จ
- นำผู้ใช้ไปยังหน้าที่เหมาะสมตามบทบาท
- แสดงข้อความแจ้งเตือนเมื่อเข้าสู่ระบบไม่สำเร็จ
- รองรับกรณีบัญชีถูกระงับการใช้งาน
- มีทางเลือกไปยังการสมัครสมาชิกและการรีเซ็ตรหัสผ่าน

### Out of scope

- การสมัครสมาชิกบัญชีใหม่ (UC-02)
- การจัดการข้อมูลบัญชีผู้ใช้ (UC-08)
- การจัดการข้อมูลหอพักโดยเจ้าของหอพัก
- การอนุมัติหอพักโดย Admin
- การเปลี่ยนแปลงสิทธิ์ของผู้ใช้
- การจัดการระบบหลังจากเข้าสู่ระบบสำเร็จของแต่ละบทบาท

## Constraints

- CON-LOGIN-01 ผู้ใช้ต้องมีบัญชีที่ลงทะเบียนในระบบก่อนจึงจะสามารถเข้าสู่ระบบได้
- CON-LOGIN-02 ระบบต้องตรวจสอบสถานะบัญชีก่อนอนุญาตให้เข้าสู่ระบบ
- CON-LOGIN-03 ระบบต้องกำหนดสิทธิ์การใช้งานจากบทบาทของบัญชี
- CON-LOGIN-04 ระบบต้องไม่เปิดเผยว่าชื่อผู้ใช้/อีเมลหรือรหัสผ่านเป็นข้อมูลที่ผิดเมื่อการเข้าสู่ระบบไม่สำเร็จ
- CON-LOGIN-05 ข้อมูลที่ใช้ในการเข้าสู่ระบบต้องถูกส่งผ่านช่องทางที่มีการเข้ารหัส
- CON-LOGIN-06 การเข้าสู่ระบบต้องไม่สร้าง session หากการยืนยันตัวตนไม่สำเร็จ

## Requirements

- FR-LOGIN-01 ระบบต้องให้ผู้ใช้กรอกชื่อผู้ใช้หรืออีเมลและรหัสผ่านเพื่อเข้าสู่ระบบ
- FR-LOGIN-02 ระบบต้องตรวจสอบข้อมูลบัญชีและรหัสผ่านก่อนอนุญาตให้เข้าสู่ระบบ
- FR-LOGIN-03 ระบบต้องตรวจสอบสถานะบัญชี หากบัญชีถูกระงับต้องไม่อนุญาตให้เข้าสู่ระบบ
- FR-LOGIN-04 เมื่อเข้าสู่ระบบสำเร็จ ระบบต้องสร้าง session สำหรับผู้ใช้
- FR-LOGIN-05 ระบบต้องกำหนดสิทธิ์การใช้งานตามบทบาทของผู้ใช้
- FR-LOGIN-06 ระบบต้องนำผู้ใช้ไปยังหน้าที่เหมาะสมตามบทบาทหลังเข้าสู่ระบบสำเร็จ
- FR-LOGIN-07 หากข้อมูลเข้าสู่ระบบไม่ถูกต้อง ระบบต้องแสดงข้อความแจ้งเตือนและให้ผู้ใช้ลองใหม่
- FR-LOGIN-08 หากผู้ใช้ยังไม่มีบัญชี ระบบต้องมีทางเลือกให้ไปยังหน้าสมัครสมาชิก
- FR-LOGIN-09 หากผู้ใช้ลืมรหัสผ่าน ระบบต้องมีทางเลือกให้ไปยังกระบวนการรีเซ็ตรหัสผ่าน

## Quality Requirements

- NFR-LOGIN-01 ระบบต้องตอบสนองการเข้าสู่ระบบภายใน 2 วินาทีในสภาวะการใช้งานปกติ
- NFR-LOGIN-02 รหัสผ่านต้องได้รับการปกป้องและไม่จัดเก็บในรูปแบบ plain text
- NFR-LOGIN-03 ข้อมูลการเข้าสู่ระบบต้องรับส่งผ่าน HTTPS
- NFR-LOGIN-04 หน้าจอเข้าสู่ระบบต้องใช้งานง่ายและไม่ซับซ้อน
- NFR-LOGIN-05 ระบบต้องไม่สร้าง session เมื่อการเข้าสู่ระบบไม่สำเร็จ

## Acceptance Criteria

- [ ] AC-LOGIN-01 (FR-LOGIN-01, FR-LOGIN-02)
      Given ผู้ใช้มีบัญชีที่ลงทะเบียนและใช้งานได้
      When ผู้ใช้กรอกชื่อผู้ใช้หรืออีเมลและรหัสผ่านที่ถูกต้องแล้วกดยืนยัน
      Then ระบบตรวจสอบข้อมูลและอนุญาตให้เข้าสู่ระบบ

- [ ] AC-LOGIN-02 (FR-LOGIN-04, FR-LOGIN-05, FR-LOGIN-06)
      Given ผู้ใช้กรอกข้อมูลเข้าสู่ระบบถูกต้อง
      When ระบบยืนยันตัวตนสำเร็จ
      Then ระบบสร้าง session กำหนดสิทธิ์ตามบทบาท และนำผู้ใช้ไปยังหน้าที่เหมาะสม

- [ ] AC-LOGIN-03 (FR-LOGIN-07)
      Given ผู้ใช้กรอกข้อมูลเข้าสู่ระบบไม่ถูกต้อง
      When ผู้ใช้กดยืนยันการเข้าสู่ระบบ
      Then ระบบแสดงข้อความ "ข้อมูลเข้าสู่ระบบไม่ถูกต้อง" และไม่อนุญาตให้เข้าสู่ระบบ

- [ ] AC-LOGIN-04 (FR-LOGIN-03)
      Given บัญชีผู้ใช้มีสถานะถูกระงับ
      When ผู้ใช้พยายามเข้าสู่ระบบด้วยข้อมูลที่ถูกต้อง
      Then ระบบแจ้งว่าบัญชีถูกระงับและไม่อนุญาตให้เข้าสู่ระบบ

- [ ] AC-LOGIN-05 (FR-LOGIN-08)
      Given ผู้ใช้ยังไม่มีบัญชี
      When ผู้ใช้เลือกตัวเลือกสมัครสมาชิก
      Then ระบบนำผู้ใช้ไปยังหน้าสมัครสมาชิก

- [ ] AC-LOGIN-06 (FR-LOGIN-09)
      Given ผู้ใช้ลืมรหัสผ่าน
      When ผู้ใช้เลือก "ลืมรหัสผ่าน"
      Then ระบบนำผู้ใช้ไปยังกระบวนการรีเซ็ตรหัสผ่าน

- [ ] AC-LOGIN-07 (NFR-LOGIN-01)
      Given ระบบอยู่ในสภาวะการใช้งานปกติ
      When ผู้ใช้ส่งข้อมูลเข้าสู่ระบบ
      Then ระบบต้องตอบสนองภายใน 2 วินาที

## Assumptions & Open Questions

- ASM-01 ชื่อผู้ใช้หรืออีเมลสามารถใช้เป็นข้อมูลสำหรับระบุบัญชีในการเข้าสู่ระบบ
- ASM-02 บัญชีผู้ใช้มี role ที่ระบบกำหนดไว้ ได้แก่ Guest, Resident, Dormitory Owner และ Admin
- ASM-03 ระบบมีหน้าสมัครสมาชิกและกระบวนการรีเซ็ตรหัสผ่านแยกจาก UC-07
- ASM-04 การกำหนดสิทธิ์หลังเข้าสู่ระบบใช้ role ของบัญชีเป็นข้อมูลหลัก

### Open Questions

- OQ-01 ต้องกำหนดรายละเอียดหน้าแรกของแต่ละ role เพิ่มเติมก่อน implementation จริง
- OQ-02 ต้องยืนยันวิธีการจัดการ session ที่ทีมจะใช้ก่อนพัฒนาระบบจริง
- OQ-03 ต้องยืนยันรายละเอียดกระบวนการรีเซ็ตรหัสผ่านกับผู้รับผิดชอบ UC ที่เกี่ยวข้อง
