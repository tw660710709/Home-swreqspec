# Feature: สมัครสมาชิก (Register)
Spec ID: SPEC-REG-001 | Source: ข้อกำหนดความต้องการข้อ 17 | Use case: UC-02  
Owner: ทีมพัฒนาระบบหอพัก | Status: Draft v2 | Updated: 2569-09-19

## Goal
ผู้ใช้งานทั่วไป (Guest) สามารถลงทะเบียนสร้างบัญชีผู้ใช้งานใหม่ในระบบได้ โดยระบบตรวจสอบและตอบกลับการสมัครภายใน p95 ไม่เกิน 2 วินาทีในสภาวะเครือข่ายปกติ ใช้งานได้บนโทรศัพท์ แท็บเล็ต และเดสก์ท็อป และไม่บันทึกรหัสผ่านเป็น Plain Text

## Scope

### In scope
- กรอกข้อมูลลงทะเบียน (ชื่อ-นามสกุล, อีเมล, เบอร์โทรศัพท์, รหัสผ่าน, ยืนยันรหัสผ่าน)
- ตรวจสอบความถูกต้องของรูปแบบข้อมูลและการซ้ำของอีเมล/เบอร์โทรศัพท์
- เข้ารหัสผ่านก่อนบันทึกลงฐานข้อมูล
- บันทึกบัญชีผู้ใช้ใหม่และแจ้งผลการสมัครสมาชิกสำเร็จ

### Out of scope
- การยืนยันตัวตนด้วยรหัส OTP ผ่าน SMS หรือ Email Verification (แยกเป็นฟีเจอร์ความปลอดภัยเพิ่มเติมในอนาคต)
- การเข้าสู่ระบบหลังสมัครสำเร็จ (UC-07)
- การแก้ไขข้อมูลส่วนตัวหลังมีบัญชีแล้ว (UC-08)

## Constraints
- CON-SEC-01 รหัสผ่านต้องมีความยาวไม่น้อยกว่า 8 ตัวอักษร และต้องผ่านการแฮชด้วย Argon2id ก่อนบันทึกลงฐานข้อมูล
- CON-DAT-01 อีเมลต้องเป็นไปตามรูปแบบอีเมลมาตรฐานและแปลงเป็นตัวพิมพ์เล็กก่อนตรวจซ้ำ ส่วนเบอร์โทรศัพท์ต้องเป็นตัวเลข 10 หลักและตัดช่องว่างหรือเครื่องหมายขีดก่อนตรวจซ้ำ ทั้งสองค่าต้องไม่ซ้ำกับข้อมูลที่มีอยู่ในระบบ (Unique Constraint)
- CON-UI-01 แบบฟอร์มต้องรองรับการกรอกข้อมูลและแสดงผลแบบ Responsive ที่ความกว้างหน้าจอ 320-767 พิกเซล (โทรศัพท์), 768-1023 พิกเซล (แท็บเล็ต) และตั้งแต่ 1024 พิกเซลขึ้นไป (เดสก์ท็อป)

## Requirements
- FR-REG-01 ระบบต้องแสดงแบบฟอร์มการลงทะเบียนที่ประกอบด้วยช่องชื่อ-นามสกุล, อีเมล, เบอร์โทรศัพท์, รหัสผ่าน และยืนยันรหัสผ่าน โดยชื่อ-นามสกุลเป็นข้อมูลจำเป็น <- UC-02 main flow ขั้น 2
- FR-REG-02 ระบบต้องตรวจสอบข้อมูลแบบ Inline Validation หลังผู้ใช้ออกจากแต่ละช่อง และตรวจสอบซ้ำเมื่อผู้ใช้กดยืนยันการสมัคร โดยตรวจสอบรูปแบบอีเมล รูปแบบเบอร์โทรศัพท์ ความยาวรหัสผ่าน และรหัสผ่านสองช่องต้องตรงกัน <- UC-02 main flow ขั้น 4
- FR-REG-03 เมื่อตรวจสอบผ่านและข้อมูลไม่ซ้ำ ระบบต้องบันทึกบัญชีผู้ใช้ใหม่ลงฐานข้อมูล พร้อมเข้ารหัสผ่าน <- UC-02 main flow ขั้น 5
- FR-REG-04 เมื่อบันทึกสำเร็จ ระบบต้องนำทางไปยังหน้าเข้าสู่ระบบทันทีและแสดงข้อความแจ้งเตือน "สมัครสมาชิกสำเร็จ" บนหน้าเข้าสู่ระบบ <- UC-02 main flow ขั้น 6
- FR-REG-05 หากผู้ใช้กดลิงก์ "มีบัญชีอยู่แล้ว? เข้าสู่ระบบ" ระบบต้องนำทางไปยังหน้าเข้าสู่ระบบ (UC-07) ทันที <- UC-02 alternative 1a
- FR-REG-06 หากข้อมูลจำเป็นไม่ครบถ้วน หรือรหัสผ่านไม่ตรงกัน ระบบต้องแสดงข้อความแจ้งเตือนที่จุดผิดพลาด และอนุญาตให้แก้ไข <- UC-02 exception 4a
- FR-REG-07 หากอีเมลหรือเบอร์โทรศัพท์ซ้ำกับที่มีอยู่ในระบบ ระบบต้องแสดงข้อความที่ช่องที่ซ้ำว่า "อีเมลนี้ถูกลงทะเบียนแล้ว" หรือ "เบอร์โทรศัพท์นี้ถูกลงทะเบียนแล้ว" พร้อมเสนอลิงก์เข้าสู่ระบบ โดยไม่สร้างบัญชีซ้ำ และหากซ้ำทั้งสองค่าต้องแสดงข้อผิดพลาดทั้งสองช่อง <- UC-02 exception 4b

## Quality Requirements
- NFR-USE-01 แบบฟอร์มต้องมีป้ายกำกับตรงกับข้อมูลที่รับ มีข้อความผิดพลาดที่ช่องที่เกี่ยวข้อง และแสดง Inline Validation หลังผู้ใช้ออกจากช่อง (Req #17)
- NFR-SEC-01 การรับส่งข้อมูลการลงทะเบียนทั้งหมดต้องใช้ HTTPS (TLS 1.2 ขึ้นไป) และระบบต้องไม่บันทึกรหัสผ่านเป็น Plain Text
- NFR-PERF-01 วัดตั้งแต่ผู้ใช้กดยืนยันการสมัครจนระบบตอบกลับผลการตรวจสอบและบันทึกข้อมูล โดยเวลาตอบสนองต้องมีค่า p95 <= 2 วินาทีในสภาวะเครือข่ายปกติ

## Acceptance Criteria
- [ ] AC-REG-01 (FR-REG-01, FR-REG-02, FR-REG-03, FR-REG-04, CON-SEC-01, NFR-SEC-01)
      Given ผู้ใช้กรอกข้อมูลถูกต้องครบถ้วน และอีเมล/เบอร์โทรศัพท์ยังไม่เคยลงทะเบียน
      When  ผู้ใช้กดยืนยันการสมัคร
      Then  ระบบบันทึกบัญชีสำเร็จด้วยรหัสผ่านที่แฮชด้วย Argon2id ผ่าน HTTPS โดยไม่บันทึกรหัสผ่านแบบ Plain Text และนำทางไปหน้าเข้าสู่ระบบพร้อมแสดงข้อความ "สมัครสมาชิกสำเร็จ"
- [ ] AC-REG-02 (FR-REG-06)
      Given ผู้ใช้กรอกรหัสผ่านในช่องรหัสผ่านและช่องยืนยันรหัสผ่านไม่ตรงกัน
      When  ผู้ใช้กดยืนยันการสมัคร
      Then  ระบบแสดงข้อความแจ้งเตือน "รหัสผ่านไม่ตรงกัน" และไม่บันทึกข้อมูล
- [ ] AC-REG-03 (FR-REG-07)
      Given มีบัญชีที่ใช้อีเมล "user@example.com" อยู่ในระบบแล้ว
      When  ผู้ใช้ใหม่พยายามลงทะเบียนด้วยอีเมล "user@example.com"
      Then  ระบบแสดงข้อความแจ้งเตือน "อีเมลนี้ถูกลงทะเบียนแล้ว" ที่ช่องอีเมล พร้อมเสนอลิงก์เข้าสู่ระบบ และไม่มีการสร้างรายการบัญชีใหม่
- [ ] AC-REG-04 (FR-REG-05)
      Given ผู้ใช้อยู่ในหน้าแบบฟอร์มสมัครสมาชิก
      When  ผู้ใช้กดลิงก์ "มีบัญชีอยู่แล้ว? เข้าสู่ระบบ"
      Then  ระบบนำทางไปยังหน้าเข้าสู่ระบบ (UC-07) ทันที
- [ ] AC-REG-05 (NFR-PERF-01)
      Given ผู้ใช้กดยืนยันการสมัครด้วยข้อมูลที่ถูกต้อง
      When  ระบบดำเนินการตรวจสอบและบันทึกข้อมูล
      Then  เวลาตอบสนองการบันทึกต้องเสร็จสิ้นภายใน 2 วินาที

## Assumptions & Open Questions
- ASM-01 ผู้ใช้ที่สมัครสมาชิกผ่านหน้านี้จะได้รับบทบาทเริ่มต้นเป็น "ผู้ใช้งานทั่วไป / Resident" โดยอัตโนมัติ
- ASM-02 ฟีเจอร์นี้รองรับเฉพาะการสมัครของ Resident ส่วน Dormitory Owner ใช้กระบวนการหรือการอนุมัติแยกต่างหาก
- ASM-03 อีเมลตรวจซ้ำแบบไม่คำนึงถึงตัวพิมพ์เล็ก-ใหญ่ และเบอร์โทรศัพท์ตรวจซ้ำหลังตัดช่องว่างหรือเครื่องหมายขีด
- ASM-04 การตรวจสอบแบบ Inline Validation ทำหลังผู้ใช้ออกจากช่อง และระบบตรวจสอบข้อมูลทั้งหมดซ้ำเมื่อกดยืนยัน
- ASM-05 หากข้อมูลซ้ำทั้งอีเมลและเบอร์โทรศัพท์ ระบบแสดงข้อผิดพลาดทั้งสองช่องพร้อมกันและคงข้อมูลช่องอื่นไว้ให้แก้ไข
- ASM-06 การนำทางหลังสมัครสำเร็จเกิดขึ้นทันทีหลังระบบตอบกลับสำเร็จ โดยข้อความสำเร็จแสดงบนหน้าเข้าสู่ระบบ
- ASM-07 ช่วงความกว้างหน้าจอสำหรับ Responsive คือ 320-767 พิกเซลสำหรับโทรศัพท์, 768-1023 พิกเซลสำหรับแท็บเล็ต และตั้งแต่ 1024 พิกเซลขึ้นไปสำหรับเดสก์ท็อป
- ASM-08 ฟีเจอร์นี้ไม่บังคับ Email Activation Link และไม่กำหนดนโยบายรหัสผ่านซับซ้อนนอกเหนือจากความยาวขั้นต่ำ 8 ตัวอักษร
