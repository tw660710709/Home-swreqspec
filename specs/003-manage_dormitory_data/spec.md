# Feature: จัดการข้อมูลหอพัก (Dormitory Management)

Spec ID: SPEC-DOR-003 | Source: ข้อกำหนดความต้องการข้อ 12, 18 | Use case: UC-03

Owner: ทีมพัฒนาระบบหอพัก | Status: Draft v2 | Updated: 2569-11-13

## Goal

เจ้าของหอพักสามารถเพิ่ม แก้ไข และอัปเดตข้อมูลหอพักของตนเองได้อย่างถูกต้องและเป็นปัจจุบัน เพื่อให้ข้อมูลที่แสดงต่อผู้เช่ามีความครบถ้วนและตรงกับสภาพจริงของหอพัก

## Use Case: UC-03 - จัดการข้อมูลหอพัก

### Actor

* Primary Actor: เจ้าของหอพัก
* Admin ตรวจสอบ/อนุมัติข้อมูลผ่าน UC-13 ซึ่งอยู่นอกขอบเขต UC-03; ใน UC-03 ระบบแสดงข้อมูลและสถานะตาม FR-DOR-15 และ DOM-RULE-01 เท่านั้น

### Preconditions

1. เจ้าของหอพักเข้าสู่ระบบและผ่านการยืนยันตัวตนแล้ว (CON-ACC-01)
2. เจ้าของหอพักมีสิทธิ์จัดการข้อมูลหอพักของตนเองเท่านั้น (CON-AUTH-01, ASM-07)
3. กรณีเพิ่มหอพักใหม่ เจ้าของหอพักสามารถเข้าถึงรายการหอพักที่มีทางเลือกเพิ่มหอพักใหม่ (FR-DOR-09)
4. กรณีแก้ไข มีหอพักเดิมที่เชื่อมโยงกับบัญชีของเจ้าของอยู่ในรายการให้เลือกและมีข้อมูลเดิมสำหรับแสดงในแบบฟอร์ม (FR-DOR-11, ASM-07)

### Main Success Flow

1. เจ้าของหอพักเลือกเมนูจัดการข้อมูลหอพัก
2. ระบบแสดงรายการหอพักที่เป็นของเจ้าของหอพักพร้อมปุ่มเพิ่มหอพักใหม่และแก้ไขข้อมูล
3. เจ้าของหอพักเลือกหอพักที่ต้องการแก้ไข
4. ระบบแสดงแบบฟอร์มข้อมูลหอพักเดิม
5. เจ้าของหอพักแก้ไขข้อมูลหอพักและข้อมูลเสริมตามที่กำหนด โดยไม่แก้ไขรหัสหอพักหรือข้อมูลที่ระบบสร้างอัตโนมัติ
6. เจ้าของหอพักเลือกอัปโหลดรูปภาพหอพักตามเงื่อนไขที่ระบบกำหนด
7. ระบบตรวจสอบความครบถ้วนและความถูกต้องของข้อมูลและไฟล์ก่อนบันทึก โดยแจ้งเตือนเป็นรายช่องพร้อมสาเหตุที่ต้องแก้ไข หากไม่มีข้อผิดพลาดแล้วให้ดำเนินการต่อ
8. เจ้าของหอพักกดยืนยันการบันทึก
9. ระบบบันทึกข้อมูลลงฐานข้อมูลและแสดงข้อมูลล่าสุดแก่เจ้าของหอพักและ Admin หากข้อมูลอยู่ระหว่างรออนุมัติ ระบบแสดงสถานะ “รออนุมัติ” และไม่แสดงข้อมูลดังกล่าวแก่ผู้ใช้งานทั่วไป

### Alternative Flow

* Alternative 2a: หากเจ้าของหอพักเลือกเพิ่มหอพักใหม่จากรายการ
  1. ระบบแสดงฟอร์มข้อมูลหอพักที่ว่างสำหรับกรอกข้อมูลใหม่
  2. เจ้าของหอพักกรอกข้อมูลหอพักที่จำเป็นและข้อมูลเสริมตาม FR-DOR-10 และ ASM-15 โดยไม่ต้องกรอกราคาห้องพักในฟอร์มนี้
  3. ระบบตรวจสอบข้อมูลหอพักก่อนบันทึก
  4. เจ้าของหอพักกดยืนยันการบันทึก
  5. ระบบบันทึกข้อมูลหอพักและแสดงข้อมูลล่าสุดตาม FR-DOR-15
  6. หลังบันทึกหอพักสำเร็จ เจ้าของหอพักเข้าสู่หน้าจัดการข้อมูลห้องพักที่แยกจากหน้าจัดการข้อมูลหอพัก
  7. ระบบแสดงข้อมูลห้องพักที่เชื่อมโยงกับหอพักที่เลือก โดยหอพักหนึ่งแห่งมีห้องพักได้หลายห้อง
  8. เจ้าของหอพักเพิ่มข้อมูลห้องพักและกำหนดราคาต่อห้องต่อเดือนในหน้าจัดการข้อมูลห้องพักตาม FR-DOR-12, ASM-16 และ ASM-17

* Alternative 5a: หากเจ้าของหอพักกดปุ่ม “ยกเลิก” ระหว่างการแก้ไขข้อมูลหอพัก
  1. ระบบไม่บันทึกการเปลี่ยนแปลงใด ๆ
  2. ระบบกลับไปยังหน้ารายการหอพัก
  3. ระบบใช้ข้อมูลเดิมจากฐานข้อมูลเพื่อแสดงในหน้ารายการ

> Flow การสร้างหอพักแยกจากการเพิ่มข้อมูลห้องพักและราคา: เจ้าของหอพักบันทึกข้อมูลหอพักก่อน แล้วจึงเพิ่มข้อมูลห้องพักและราคาต่อห้องในหน้าจอแยก (FR-DOR-12, ASM-16, ASM-17)

### Exception Flow

* Exception 7a: หากข้อมูลจำเป็นไม่ครบถ้วนหรือไม่ถูกต้อง
  1. ระบบแสดงข้อความแจ้งเตือนเป็นรายช่องพร้อมสาเหตุที่ต้องแก้ไข เช่น “กรุณากรอกชื่อหอพัก” หรือ “กรุณากรอกที่อยู่/ทำเล”
 2. ระบบไม่บันทึกข้อมูลจนกว่าจะปรับข้อมูลให้ถูกต้องครบถ้วนตาม FR-DOR-17 และ AC-DOR-09

* Exception 7b: หากเลือกอัปโหลดรูปภาพที่ไม่ตรงตามเงื่อนไขหรือเกินจำนวนที่กำหนด
  1. ระบบปฏิเสธเฉพาะไฟล์ที่ไม่ตรงตามเงื่อนไขหรือเกินจำนวนที่กำหนด
  2. ระบบแจ้งสาเหตุที่ชัดเจน เช่น “ไฟล์ต้องเป็น JPG, JPEG หรือ PNG และไม่เกิน 5 MB” หรือ “อัปโหลดได้ไม่เกิน 10 รูป”
 3. ระบบยังรับไฟล์ที่ถูกต้องตามปกติ และให้เจ้าของหอพักเลือกไฟล์ใหม่แทนไฟล์ที่ถูกปฏิเสธได้ตาม FR-DOR-18 และ AC-DOR-10

### Postconditions

* Success
  - ข้อมูลหอพักถูกบันทึกลงฐานข้อมูลโดยสมบูรณ์
  - ข้อมูลล่าสุดแสดงให้เจ้าของหอพักและ Admin เห็นได้
  - หากข้อมูลอยู่ระหว่างรออนุมัติ ระบบแสดงสถานะ “รออนุมัติ” และไม่แสดงต่อผู้ใช้งานทั่วไป

* Cancelled
  - ไม่มีการบันทึกการเปลี่ยนแปลงใด ๆ
  - ระบบกลับไปยังหน้ารายการหอพักและใช้ข้อมูลเดิมจากฐานข้อมูล

* Validation Failure
  - ข้อมูลที่ไม่ครบถ้วนหรือไม่ถูกต้องไม่ถูกบันทึก
  - เจ้าของหอพักต้องแก้ไขข้อมูลก่อนจะสามารถบันทึกได้อีกครั้ง

* File Rejection
  - ไฟล์ที่ไม่ตรงตามเงื่อนไขถูกปฏิเสธเฉพาะไฟล์นั้น
  - ไฟล์ที่ถูกต้องยังคงถูกยอมรับและให้เจ้าของหอพักเลือกไฟล์ใหม่แทนได้

## Scope

### In scope

* แสดงรายการหอพักที่เป็นของเจ้าของหอพักที่เข้าสู่ระบบ
* เพิ่มข้อมูลหอพักใหม่
* แก้ไขข้อมูลหอพักที่มีอยู่
* เพิ่มและแก้ไขข้อมูลห้องพักและราคาค่าเช่าต่อห้องต่อเดือน (บาท/เดือน) หลังบันทึกข้อมูลหอพักสำเร็จ ผ่านหน้าจัดการข้อมูลห้องพักที่แยกจากหน้าจัดการข้อมูลหอพัก โดยหอพักหนึ่งแห่งมีห้องพักได้หลายห้องและข้อมูลห้องพักเชื่อมโยงกับหอพัก
* แก้ไขข้อมูลสิ่งอำนวยความสะดวก
* แก้ไขกฎระเบียบของหอพัก
* แก้ไขช่องทางการติดต่อ
* อัปโหลดและเปลี่ยนรูปภาพหอพักหรือห้องพัก
* ตรวจสอบความครบถ้วนและความถูกต้องของข้อมูลก่อนบันทึก
* บันทึกข้อมูลหอพักลงในฐานข้อมูล
* แสดงข้อมูลล่าสุดหลังจากบันทึกสำเร็จ

### Out of scope

* การค้นหาและดูข้อมูลหอพักของผู้ใช้งานทั่วไป (UC-01)
* การนัดหมายเพื่อดูห้องพัก (UC-06)
* การจองห้องพัก (UC-12)
* การตรวจสอบและอนุมัติข้อมูลหอพักโดย Admin (UC-13)
* การจัดการข้อมูลหอพักของเจ้าของหอพักรายอื่น

## Constraints

* CON-ACC-01 เจ้าของหอพักต้องเข้าสู่ระบบและผ่านการยืนยันตัวตนก่อนจัดการข้อมูลหอพัก
* CON-AUTH-01 เจ้าของหอพักสามารถจัดการได้เฉพาะข้อมูลหอพักที่เป็นของตนเอง
* CON-DATA-01 ระบบต้องตรวจสอบข้อมูลที่จำเป็นก่อนบันทึก โดยข้อมูลหอพักที่จำเป็นประกอบด้วยชื่อหอพัก, ที่อยู่/ทำเล, ประเภทหอพัก และช่องทางติดต่อ ส่วนสิ่งอำนวยความสะดวก กฎระเบียบ และรูปภาพเป็นข้อมูลเสริม ราคาค่าเช่าต่อห้องต่อเดือน (บาท/เดือน) เป็นข้อมูลจำเป็นของห้องพักและกำหนดในหน้าจัดการข้อมูลห้องพักที่แยกจากหน้าจัดการข้อมูลหอพัก
* CON-FILE-01 รูปภาพที่อัปโหลดต้องเป็นไฟล์ประเภท JPG, JPEG หรือ PNG ขนาดไม่เกิน 5 MB ต่อไฟล์ และไม่เกิน 10 รูปต่อหอพัก/ห้องพัก หากมีไฟล์ไม่ตรงตามเงื่อนไขหรือเกินจำนวนที่กำหนด ระบบต้องปฏิเสธเฉพาะไฟล์ที่ไม่ถูกต้องและยังรับไฟล์ที่ถูกต้องได้
* CON-BUS-01 ข้อมูลที่แก้ไขจะต้องถูกบันทึกลงในฐานข้อมูลก่อนจึงจะแสดงเป็นข้อมูลล่าสุด
* DOM-RULE-01 ข้อมูลหอพักและรูปภาพที่เจ้าของหอพักบันทึกต้องตรงกับสภาพและเงื่อนไขจริงของหอพัก และเจ้าของหอพักรับผิดชอบข้อมูลที่กรอก ขณะที่ Admin เป็นผู้ตรวจสอบ/อนุมัติ (Req #18) ข้อมูลที่บันทึกแล้วและรอการอนุมัติต้องแสดงสถานะ “รออนุมัติ” โดยเจ้าของหอพักและ Admin ดูข้อมูลได้ แต่ผู้ใช้งานทั่วไปยังดูข้อมูลดังกล่าวไม่ได้

## Requirements

* FR-DOR-09 ระบบต้องแสดงรายการหอพักที่เป็นของเจ้าของหอพักที่เข้าสู่ระบบ พร้อมปุ่มเพิ่มหอพักใหม่และแก้ไขข้อมูล
* FR-DOR-10 ระบบต้องให้เจ้าของหอพักสามารถเพิ่มข้อมูลหอพักใหม่ได้ โดยต้องกรอกข้อมูลหอพักที่จำเป็นให้ครบถ้วนก่อนบันทึก ได้แก่ ชื่อหอพัก, ที่อยู่/ทำเล, ประเภทหอพัก และช่องทางติดต่อ ส่วนสิ่งอำนวยความสะดวก กฎระเบียบ และรูปภาพเป็นข้อมูลเสริม ราคาค่าเช่าต่อห้องต่อเดือน (บาท/เดือน) เป็นข้อมูลจำเป็นของห้องพักและกำหนดผ่านหน้าจัดการข้อมูลห้องพักที่แยกจากหน้าจัดการข้อมูลหอพัก
* FR-DOR-11 ระบบต้องแสดงแบบฟอร์มข้อมูลหอพักเดิมเมื่อเจ้าของหอพักเลือกแก้ไขข้อมูล
* FR-DOR-12 ระบบต้องให้เจ้าของหอพักสามารถแก้ไขชื่อหอพัก ที่อยู่ ประเภท สิ่งอำนวยความสะดวก กฎระเบียบ รูปภาพ และช่องทางการติดต่อได้ โดยการเพิ่มและจัดการข้อมูลห้องพักรวมถึงราคาค่าเช่าต่อห้องต่อเดือน (บาท/เดือน) ทำผ่านหน้าจอแยกจากหน้าจัดการข้อมูลหอพักหลังบันทึกข้อมูลหอพักสำเร็จ และหอพักหนึ่งแห่งสามารถมีห้องพักได้หลายห้อง ส่วนรหัสหอพักและข้อมูลที่ระบบสร้างอัตโนมัติแก้ไขไม่ได้ (Req #12)
* FR-DOR-13 ระบบต้องตรวจสอบความครบถ้วนและความถูกต้องของข้อมูลก่อนบันทึก โดยแจ้งเตือนเป็นรายช่องและระบุสาเหตุที่ต้องแก้ไข เช่น “กรุณากรอกชื่อหอพัก” หรือ “ไฟล์ต้องเป็น JPG, JPEG หรือ PNG และไม่เกิน 5 MB”
* FR-DOR-14 ระบบต้องสามารถอัปโหลดและจัดเก็บรูปภาพหอพักหรือห้องพักตามเงื่อนไขของระบบ โดยรองรับไฟล์ JPG, JPEG, PNG ขนาดไม่เกิน 5 MB ต่อไฟล์ และไม่เกิน 10 รูปต่อหอพัก/ห้องพัก หากมีไฟล์ไม่ตรงตามเงื่อนไขหรือเกินจำนวนที่กำหนด ระบบต้องปฏิเสธเฉพาะไฟล์ที่ไม่ถูกต้องและยังรับไฟล์ที่ถูกต้องได้
* FR-DOR-15 เมื่อบันทึกข้อมูลสำเร็จ ระบบต้องอัปเดตข้อมูลหอพักในฐานข้อมูลและแสดงข้อมูลล่าสุดแก่เจ้าของหอพักและ Admin หากข้อมูลอยู่ระหว่างรออนุมัติ ระบบต้องแสดงสถานะ “รออนุมัติ” และไม่แสดงข้อมูลดังกล่าวแก่ผู้ใช้งานทั่วไป
* FR-DOR-16 หากเจ้าของหอพักยกเลิกการแก้ไข ระบบต้องไม่บันทึกการเปลี่ยนแปลง กลับไปยังหน้ารายการหอพัก และใช้ข้อมูลเดิมจากฐานข้อมูล
* FR-DOR-17 หากข้อมูลจำเป็นไม่ครบถ้วน ระบบต้องแจ้งเตือนเป็นรายช่องพร้อมสาเหตุที่ต้องแก้ไขก่อนบันทึก และไม่บันทึกข้อมูล
* FR-DOR-18 หากไฟล์รูปภาพไม่ตรงตามเงื่อนไขหรือเกินจำนวนที่กำหนด ระบบต้องปฏิเสธเฉพาะไฟล์ดังกล่าวและแจ้งเตือนพร้อมสาเหตุที่ชัดเจน เช่น “ไฟล์ต้องเป็น JPG, JPEG หรือ PNG และไม่เกิน 5 MB” หรือ “อัปโหลดได้ไม่เกิน 10 รูป” โดยยังรับไฟล์ที่ถูกต้องและให้เจ้าของหอพักเลือกไฟล์ใหม่แทนไฟล์ที่ถูกปฏิเสธได้

## Quality Requirements

* NFR-USE-02 แบบฟอร์มสำหรับเพิ่มและแก้ไขข้อมูลหอพักต้องใช้งานง่ายและไม่ซับซ้อน: ผู้ใช้งานอย่างน้อย 90% ของผู้ทดสอบต้องสามารถเพิ่มหรือแก้ไขข้อมูลหอพักได้สำเร็จโดยไม่ต้องได้รับความช่วยเหลือจากผู้อื่น และไม่เกิดข้อผิดพลาดร้ายแรงที่ทำให้กระบวนการบันทึกหยุดชะงัก สูญเสียข้อมูล หรือทำให้ผู้ใช้ต้องเริ่มใหม่ การทดสอบจะดำเนินการแบบ usability testing กับผู้ใช้งานจริงที่มีประสบการณ์ระดับปกติ โดยให้ทำภารกิจเพิ่มหอพักใหม่และแก้ไขข้อมูลหอพักที่มีอยู่ บันทึกเปอร์เซ็นต์ความสำเร็จ จำนวนครั้งที่ต้องได้รับความช่วยเหลือ และข้อผิดพลาดร้ายแรง เพื่อยอมรับว่าเป็นไปตามข้อกำหนดเมื่อมีความสำเร็จไม่น้อยกว่า 90% และไม่มีข้อผิดพลาดร้ายแรงที่ส่งผลต่อข้อมูลหรือการทำงาน
* NFR-DATA-02 ข้อมูลและรูปภาพของหอพักที่จัดเก็บในระบบต้องตรงกับข้อมูลและสภาพจริงของหอพัก (Req #18) ข้อมูลที่รออนุมัติยังไม่แสดงต่อผู้ใช้งานทั่วไป
* NFR-SEC-02 ระบบต้องป้องกันไม่ให้เจ้าของหอพักเข้าถึงหรือแก้ไขข้อมูลของเจ้าของหอพักรายอื่น

## Acceptance Criteria

* [ ] AC-DOR-07 (FR-DOR-09, FR-DOR-11, NFR-SEC-02)

  ```
  Given เจ้าของหอพักเข้าสู่ระบบเรียบร้อยแล้ว

  When เจ้าของหอพักเลือกเมนูจัดการข้อมูลหอพัก

  Then ระบบแสดงเฉพาะรายการหอพักที่เป็นของเจ้าของหอพัก พร้อมปุ่มเพิ่มหอพักใหม่และแก้ไขข้อมูล

  Scenario: เจ้าของหอพักเข้าถึงข้อมูลของเจ้าของรายอื่นไม่ได้

  Given เจ้าของหอพักเข้าสู่ระบบด้วยบัญชีของตนเอง และมีหอพักหรือห้องพักของเจ้าของรายอื่นอยู่ในระบบ

  When เจ้าของหอพักพยายามเปิดหรือแก้ไขหอพัก/ห้องพักของเจ้าของรายอื่น หรือใช้ roomId ที่ไม่ได้เชื่อมโยงกับ dormitoryId ที่ระบุ

  Then ระบบไม่อนุญาตให้เข้าถึงหรือแก้ไขข้อมูลดังกล่าว
  ```

* [ ] AC-DOR-08 (FR-DOR-10, FR-DOR-12, FR-DOR-15, NFR-USE-02)

  ```
  Scenario: บันทึกข้อมูลหอพัก

  Given เจ้าของหอพักอยู่ในหน้าแบบฟอร์มจัดการข้อมูลหอพัก

  When เจ้าของหอพักกรอกหรือแก้ไขข้อมูลหอพักและกดยืนยันการบันทึก

  Then ระบบตรวจสอบข้อมูลและบันทึกลงฐานข้อมูล จากนั้นแสดงข้อมูลล่าสุดแก่เจ้าของหอพักและ Admin หากข้อมูลรออนุมัติ ระบบแสดงสถานะ “รออนุมัติ” และไม่แสดงข้อมูลดังกล่าวแก่ผู้ใช้งานทั่วไป

  Scenario: เปิดหน้าจัดการข้อมูลห้องพัก

  Given เจ้าของหอพักเลือกจัดการข้อมูลห้องพักของหอพักแห่งหนึ่ง

  When เจ้าของหอพักเปิดหน้าจัดการข้อมูลห้องพัก

  Then ระบบแสดงหน้าจัดการข้อมูลห้องพักแยกจากหน้าจัดการข้อมูลหอพัก และแสดงข้อมูลห้องพักที่เชื่อมโยงกับหอพักที่เลือก โดยเจ้าของหอพักสามารถเพิ่มข้อมูลห้องพักและกำหนดราคาต่อห้องต่อเดือน รวมถึงจัดการหลายห้องภายใต้หอพักหนึ่งแห่งได้

  Scenario: เกณฑ์การทดสอบ usability สำหรับการเพิ่มหรือแก้ไขข้อมูลหอพัก

  Given ผู้ทดสอบจริงที่มีประสบการณ์ระดับปกติได้รับภารกิจเพิ่มหอพักใหม่หรือแก้ไขข้อมูลหอพักที่มีอยู่

  When ดำเนิน usability testing และบันทึกผลของผู้ทดสอบ

  Then ผู้ทดสอบอย่างน้อย 90% ทำภารกิจสำเร็จโดยไม่ต้องได้รับความช่วยเหลือ และไม่เกิดข้อผิดพลาดร้ายแรงที่ส่งผลต่อข้อมูลหรือการทำงาน โดยบันทึกเปอร์เซ็นต์ความสำเร็จ จำนวนครั้งที่ต้องได้รับความช่วยเหลือ และข้อผิดพลาดร้ายแรง
  ```

* [ ] AC-DOR-09 (FR-DOR-13, FR-DOR-17)

  ```
  Given เจ้าของหอพักกรอกข้อมูลไม่ครบถ้วน

  When เจ้าของหอพักกดยืนยันการบันทึก

  Then ระบบแสดงข้อความแจ้งเตือนเป็นรายช่องพร้อมสาเหตุที่ต้องแก้ไข เช่น “กรุณากรอกชื่อหอพัก” หรือ “กรุณากรอกที่อยู่/ทำเล” โดยไม่บันทึกข้อมูล

  Scenario: ข้อมูลไม่ถูกต้องตามการตรวจสอบที่กำหนด

  Given เจ้าของหอพักกรอกข้อมูลที่ระบบตรวจพบว่าไม่ถูกต้อง

  When เจ้าของหอพักกดยืนยันการบันทึก

  Then ระบบแจ้งเตือนเป็นรายช่องพร้อมสาเหตุที่ต้องแก้ไขตามการตรวจสอบที่กำหนด และไม่บันทึกข้อมูล
  ```

* [ ] AC-DOR-10 (FR-DOR-18)

  ```
  Given เจ้าของหอพักเลือกอัปโหลดรูปภาพที่ไม่ตรงตามเงื่อนไข

  When ระบบตรวจสอบไฟล์รูปภาพ

  Then ระบบปฏิเสธเฉพาะไฟล์ที่ไม่ตรงตามเงื่อนไขหรือเกินจำนวนที่กำหนด พร้อมแจ้งสาเหตุที่ชัดเจน เช่น “ไฟล์ต้องเป็น JPG, JPEG หรือ PNG และไม่เกิน 5 MB” หรือ “อัปโหลดได้ไม่เกิน 10 รูป” โดยไฟล์ที่ถูกต้องยังอัปโหลดได้ตามปกติและเจ้าของหอพักเลือกไฟล์อื่นแทนไฟล์ที่ถูกปฏิเสธได้
  ```

* [ ] AC-DOR-11 (FR-DOR-16)

  ```
  Given เจ้าของหอพักกำลังแก้ไขข้อมูลหอพัก

  When เจ้าของหอพักกดปุ่ม "ยกเลิก"

  Then ระบบไม่บันทึกการเปลี่ยนแปลง กลับไปยังหน้ารายการหอพัก และใช้ข้อมูลเดิมจากฐานข้อมูล
  ```

* [ ] AC-DOR-12 (NFR-DATA-02)

  ```
  Given เจ้าของหอพักบันทึกข้อมูลและรูปภาพของหอพักที่ได้รับอนุมัติแล้ว

  When ผู้ใช้งานทั่วไปเปิดดูข้อมูลหอพัก

  Then ระบบแสดงข้อมูลและรูปภาพล่าสุดที่ได้รับอนุมัติแล้วอย่างถูกต้อง

  Scenario: ข้อมูลที่รออนุมัติไม่แสดงต่อผู้ใช้งานทั่วไป

  Given ข้อมูลหอพักหรือรูปภาพมีสถานะ “รออนุมัติ”

  When ผู้ใช้งานทั่วไปเปิดดูข้อมูลหอพัก

  Then ระบบไม่แสดงข้อมูลหรือรูปภาพที่รออนุมัติดังกล่าวแก่ผู้ใช้งานทั่วไป
  ```

## Assumptions & Resolved Questions

* ASM-06 เจ้าของหอพักมีบัญชีผู้ใช้งานและสามารถเข้าสู่ระบบได้ก่อนใช้งาน UC-03
* ASM-07 เจ้าของหอพักสามารถจัดการได้เฉพาะหอพักที่เชื่อมโยงกับบัญชีของตนเอง
* ASM-08 ระบบมีการกำหนดประเภทไฟล์และขนาดสูงสุดของรูปภาพที่สามารถอัปโหลดได้ โดยรองรับ JPG, JPEG, PNG ขนาดไม่เกิน 5 MB ต่อไฟล์ และไม่เกิน 10 รูปต่อหอพัก/ห้องพัก
* ASM-09 การตรวจสอบและอนุมัติข้อมูลหอพักเป็นหน้าที่ของ Admin และดำเนินการใน UC-13 โดยเจ้าของหอพักรับผิดชอบข้อมูลที่กรอก
* ASM-10 การแสดงข้อมูลต่อผู้ใช้งานทั่วไประหว่างรออนุมัติการแก้ไข ยังรอคำตอบ Q-02
* ASM-11 หนึ่งบัญชีสามารถมีหลายหอพักได้
* ASM-12 ระบบเก็บเฉพาะข้อมูลล่าสุดที่บันทึกสำเร็จ ไม่เก็บ version เก่า และข้อมูลที่ยังไม่กดบันทึกจะไม่ถูกนำไปแสดงเป็นข้อมูลล่าสุด
* ASM-13 รหัสหอพักและข้อมูลที่ระบบสร้างอัตโนมัติไม่สามารถแก้ไขได้จากฟอร์มจัดการข้อมูลหอพัก
* ASM-14 ข้อมูลที่บันทึกแล้วแต่รอ Admin อนุมัติต้องมีสถานะ “รออนุมัติ” โดยเจ้าของหอพักและ Admin ดูได้ แต่ผู้ใช้งานทั่วไปดูไม่ได้
* ASM-15 ชื่อหอพัก ที่อยู่/ทำเล ประเภทหอพัก และช่องทางติดต่อเป็นข้อมูลหอพักที่จำเป็น ส่วนสิ่งอำนวยความสะดวก กฎระเบียบ และรูปภาพเป็นข้อมูลเสริม ราคาค่าเช่าต่อห้องต่อเดือนเป็นข้อมูลห้องพักที่จำเป็นและกำหนดในหน้าจัดการข้อมูลห้องพักแยกจากหน้าจัดการข้อมูลหอพัก
* ASM-16 ราคาค่าเช่าหมายถึงราคาต่อห้องต่อเดือน และแสดงหน่วยเป็นบาท/เดือน
* ASM-17 การจัดการข้อมูลห้องพักอยู่คนละหน้ากับการจัดการข้อมูลหอพัก โดยข้อมูลห้องพักเชื่อมโยงกับหอพัก และหอพักหนึ่งแห่งสามารถมีหลายห้องพักได้
* ASM-18 เมื่ออัปโหลดหลายรูป ระบบปฏิเสธเฉพาะไฟล์ที่ไม่ตรงตามเงื่อนไขหรือเกินจำนวนที่กำหนด โดยรับไฟล์ที่ถูกต้องตามปกติ
* ASM-19 ไม่ต้องมีสถานะ Draft ข้อมูลที่ยังไม่ได้กดบันทึกจะไม่ถูกจัดเก็บลงฐานข้อมูลและไม่แสดงต่อผู้ใช้งาน
