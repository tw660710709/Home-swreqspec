# แผนทางเทคนิค: จัดการข้อมูลหอพัก

ไฟล์ข้อกำหนดอ้างอิง: `spec.md`  
Spec ID: `SPEC-DOR-003` | สถานะข้อกำหนด: `Draft v2`

## 1. สรุปแนวทาง

1. สร้างหน้าจัดการข้อมูลหอพักสำหรับเจ้าของหอพักที่เข้าสู่ระบบ เพื่อแสดงรายการหอพักของตนเอง พร้อมปุ่มเพิ่ม/แก้ไขและตรวจสิทธิ์ว่ามีสิทธิ์จัดการข้อมูลที่เกี่ยวข้องเท่านั้น (`CON-ACC-01`, `CON-AUTH-01`, `FR-DOR-09`)
2. สร้างฟอร์มเพิ่ม/แก้ไขหอพักที่รองรับข้อมูลจำเป็น, ฟิลด์ที่อนุญาตแก้ไข, และการป้องกันอัปเดตฟิลด์ที่ระบบสร้างอัตโนมัติ (`FR-DOR-10`, `FR-DOR-11`, `FR-DOR-12`, `ASM-13`)
3. เพิ่มการตรวจสอบก่อนบันทึกแบบรายช่อง เพื่อยืนยันความครบถ้วนและความถูกต้องของข้อมูล รวมถึงการตรวจสอบไฟล์รูปภาพตามเงื่อนไขที่กำหนด (`CON-DATA-01`, `CON-FILE-01`, `FR-DOR-13`, `FR-DOR-14`, `FR-DOR-17`, `FR-DOR-18`)
4. สร้างกระบวนการบันทึกข้อมูลลงฐานข้อมูลหลังตรวจสอบสำเร็จ และแสดงข้อมูลล่าสุดหากบันทึกสำเร็จ หรือกลับไปใช้ข้อมูลเดิมเมื่อยกเลิก (`CON-BUS-01`, `FR-DOR-15`, `FR-DOR-16`)
5. วางโครงสร้าง API, UI และการทดสอบให้ครอบคลุม Acceptance Criteria ทั้งหมด และคงความปลอดภัยให้เจ้าของหอพักเข้าถึงเฉพาะหอพักที่เป็นของตนเอง (`NFR-SEC-02`, `FR-DOR-09` ถึง `AC-DOR-12`)

## 2. เทคโนโลยีที่ใช้

| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้าง API สำหรับดึงรายการหอพัก, ดูรายละเอียด, สร้าง/อัปเดตข้อมูลหอพัก และอัปโหลดรูปภาพ |
| ฐานข้อมูลเชิงสัมพันธ์ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บข้อมูลหอพัก, ห้องพัก, รูปภาพ, สิ่งอำนวยความสะดวก, กฎระเบียบ, ช่องทางติดต่อ และความเชื่อมโยงกับเจ้าของหอพัก |
| ระบบจัดเก็บไฟล์ภาพ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บรูปภาพที่อัปโหลดได้ตาม `CON-FILE-01` โดยต้องจำกัดประเภท/ขนาด/จำนวนรูป |
| JWT หรือ session auth ที่มีอยู่ในระบบ | `CON-ACC-01`, `CON-AUTH-01` | ใช้เพื่อยืนยันตัวตนและตรวจว่าเจ้าของหอพักมีสิทธิ์เข้าถึงหอพักที่เป็นของตนเอง |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Owner` | `owner_id`, `name`, `email`, `status` | `CON-ACC-01`, `CON-AUTH-01`, `FR-DOR-09` |
| `Dormitory` | `dormitory_id`, `owner_id`, `name`, `address`, `location`, `dormitory_type`, `price_range`, `contact_channels`, `created_at`, `updated_at`, `approval_status` | `FR-DOR-09`, `FR-DOR-10`, `FR-DOR-11`, `FR-DOR-12`, `FR-DOR-15`, `ASM-11`, `ASM-12` |
| `DormitoryRoom` | `room_id`, `dormitory_id`, `room_name`, `room_type`, `monthly_rent`, `facilities`, `status` | `FR-DOR-12`, `FR-DOR-14`, `ASM-12` |
| `Facility` | `facility_id`, `dormitory_id`, `name`, `description` | `FR-DOR-12`, `FR-DOR-14` |
| `DormitoryRule` | `rule_id`, `dormitory_id`, `title`, `description` | `FR-DOR-12` |
| `ContactChannel` | `contact_id`, `dormitory_id`, `type`, `value`, `is_primary` | `FR-DOR-12`, `FR-DOR-10`, `CON-DATA-01` |
| `DormitoryImage` | `image_id`, `dormitory_id`, `image_url`, `image_type`, `size_bytes`, `is_primary` | `FR-DOR-12`, `FR-DOR-14`, `FR-DOR-18`, `CON-FILE-01` |
| `ValidationError` (ภายใน form state หรือ response) | `field_name`, `message`, `reason_code` | `FR-DOR-13`, `FR-DOR-17`, `FR-DOR-18` |

กติกาข้อมูล:

- หอพักทุกรายการต้องเชื่อมกับ `owner_id` และต้องกรองเฉพาะหอพักที่เป็นของเจ้าของหอพักที่เข้าสู่ระบบ (`CON-AUTH-01`, `FR-DOR-09`)
- ฟิลด์ที่ถือว่า “ข้อมูลที่จำเป็น” ได้แก่ `name`, `address`, `dormitory_type`, `price_range`, `contact_channels` ตาม `CON-DATA-01` และ `FR-DOR-10`
- ฟิลด์ที่เป็นรหัสหอพักหรือข้อมูลที่ระบบสร้างอัตโนมัติจะถูกเก็บไว้แต่ไม่แสดงให้แก้ไขจากฟอร์ม (`ASM-13`)
- ไม่เก็บข้อมูลที่ไม่ได้ระบุในข้อกำหนด เช่น หลักฐานหรือข้อมูลส่วนบุคคลที่ไม่จำเป็นสำหรับงานนี้ (`Out of scope`, `CON-DATA-01`)
- ข้อมูลไม่บันทึกจะอยู่เพียงใน state ของฟอร์ม และไม่ถูกคำนึงว่าเป็นข้อมูลล่าสุดจนกว่าจะกดบันทึกสำเร็จ (`ASM-12`, `FR-DOR-16`)

## 4. API / หน้าจอ

| รายการ | Input หลัก | Output หลัก | รองรับ |
|---|---|---|---|
| `GET /owners/dormitories` | `owner_id` จาก session/token | รายการหอพักของเจ้าของหอพักที่ล็อกอินอยู่ | `FR-DOR-09`, `CON-AUTH-01` |
| `GET /owners/dormitories/{dormitoryId}` | `dormitoryId`, `owner_id` | ข้อมูลหอพักพร้อมข้อมูลที่แก้ไขได้, รูปภาพ, สิ่งอำนวยความสะดวก, กฎระเบียบ และช่องทางติดต่อ | `FR-DOR-11`, `FR-DOR-12` |
| `POST /owners/dormitories` | `name`, `address`, `dormitory_type`, `price_range`, `contact_channels`, `facilities`, `rules`, `images` | สร้างหอพักใหม่ หากข้อมูลครบถ้วนและผ่าน validation | `FR-DOR-10`, `FR-DOR-13`, `FR-DOR-15` |
| `PUT /owners/dormitories/{dormitoryId}` | ฟิลด์ที่อนุญาตแก้ไขเท่านั้น, พร้อม image payload ที่จำเป็น | อัปเดตข้อมูลหอพักและคืนสถานะสำเร็จ/ล้มเหลว | `FR-DOR-12`, `FR-DOR-13`, `FR-DOR-15` |
| `POST /owners/dormitories/{dormitoryId}/images` | file upload, metadata | คืนสถานะ upload success หรือ error ตามค่า `JPG/JPEG/PNG` และ `<= 5MB` | `FR-DOR-14`, `FR-DOR-18`, `CON-FILE-01` |
| `POST /owners/dormitories/{dormitoryId}/cancel` | `owner_id`, `dormitoryId` | ยกเลิกและกลับสู่หน้ารายการโดยไม่บันทึกการเปลี่ยนแปลง | `FR-DOR-16` |
| หน้ารายการหอพัก | login owner + selection | รายการหอพักของเจ้าของ, ปุ่มเพิ่มและแก้ไข | `FR-DOR-09`, `AC-DOR-07` |
| หน้าฟอร์มเพิ่ม/แก้ไขหอพัก | ฟิลด์ข้อมูลหอพัก + upload image + save/cancel | validation แบบรายช่อง, save success, cancel reset | `FR-DOR-10`, `FR-DOR-11`, `FR-DOR-13`, `FR-DOR-17`, `FR-DOR-18`, `AC-DOR-09`, `AC-DOR-10`, `AC-DOR-11` |
| หน้าข้อมูลล่าสุดหลังบันทึกสำเร็จ | redirect หรือ response จาก save | แสดงข้อมูลล่าสุดที่บันทึกลงฐานข้อมูลแล้ว | `FR-DOR-15`, `AC-DOR-08` |

หมายเหตุ: API และชื่อฟิลด์ด้านบนเป็นสัญญาเชิงตรรกะสำหรับการวางแผน เพื่อให้ plan ระบุวิธีสร้างที่ชัดเจน แต่ยังไม่ลงรายละเอียด implementation ที่จำเป็นต้องยืนยันต่อไป

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| `CON-ACC-01` | ตรวจสิทธิ์เข้าสู่ระบบและการเข้าถึงหน้าจัดการหอพัก | ใช้แล้ว |
| `CON-AUTH-01` | Filter รายการและ API ตาม `owner_id` เพื่อให้เจ้าของหอพักเห็นได้เฉพาะหอพักของตนเอง | ใช้แล้ว |
| `CON-DATA-01` | Validation Before Save ในฟอร์ม และ contract ของ `POST/PUT` สำหรับข้อมูลจำเป็น | ใช้แล้ว |
| `CON-FILE-01` | File validation ใน upload และ rule ตรวจประเภท/ขนาด/จำนวนรูปภาพ | ใช้แล้ว |
| `CON-BUS-01` | หลัง save ให้บันทึกลงฐานข้อมูลก่อนที่ UI จะแสดงเป็นข้อมูลล่าสุด และไม่แสดงข้อมูลที่ยังไม่ได้บันทึก | ใช้แล้ว |
| `DOM-RULE-01` | validation และ display ของข้อมูลหอพัก/รูปภาพสำหรับเจ้าของและผู้ใช้งานทั่วไปตามความเป็นจริง | ใช้แล้ว |

## 7. ลำดับงาน

1. สร้างโครงหน้า Dashboard และฟอร์มจัดการหอพัก โดยยึดสิทธิ์เจ้าของหอพักและ layout ความง่ายใช้งานตาม `FR-DOR-09`, `NFR-USE-02`, `CON-AUTH-01`
2. สร้าง entities/service สำหรับข้อมูลหอพัก, รูปภาพ, สิ่งอำนวยความสะดวก, กฎระเบียบ, และช่องทางติดต่อ ตาม `FR-DOR-10`, `FR-DOR-11`, `FR-DOR-12`
3. สร้าง validation สำหรับข้อมูลที่จำเป็นและ upload file ตาม `CON-DATA-01`, `CON-FILE-01`, `FR-DOR-13`, `FR-DOR-14`, `FR-DOR-17`, `FR-DOR-18`
4. สร้าง API สำหรับดึงและบันทึกข้อมูลหอพัก และตรวจ permission ก่อนจัดการข้อมูลตาม `CON-ACC-01`, `CON-AUTH-01`, `FR-DOR-15`
5. เพิ่ม UX สำหรับสถานะ success/error/cancel พร้อมการกลับสู่รายการหอพักตาม `FR-DOR-15`, `FR-DOR-16`, `FR-DOR-17`, `FR-DOR-18`
6. บูรณาการการแสดงข้อมูลล่าสุดหลังบันทึกสำเร็จ และปรับ state ให้ไม่แสดงข้อมูลยังไม่บันทึกตาม `CON-BUS-01`, `ASM-12`
7. ทดสอบตาม Acceptance Criteria ทุกข้อ และตรวจเรื่อง permission ความถูกต้องของข้อมูลและรูปภาพตาม `AC-DOR-07` ถึง `AC-DOR-12`
8. ตรวจความมั่นคงของการป้องกันการเข้าถึงข้อมูลของเจ้าของรายอื่นและตรวจผิดพลาดใน UI ตาม `NFR-SEC-02` และ `AC-DOR-07`

## 8. สิ่งที่ยังไม่ทำ

ปัจจุบัน spec นี้ไม่มี Open Questions ค้างอยู่ในหัวข้อ Open Questions จึงไม่มีส่วนที่ต้องหยุดการพัฒนาไว้ก่อน เพราะยังไม่มีคำถามที่ต้องรอคำตอบจากทีม

สิ่งที่ไม่รวมอยู่ในแผนนี้ และมีชัดเจนใน Out of scope ได้แก่:

- การค้นหาและดูข้อมูลหอพักของผู้ใช้งานทั่วไป (UC-01)
- การนัดหมายเพื่อดูห้องพัก (UC-06)
- การจองห้องพัก (UC-12)
- การตรวจสอบและอนุมัติข้อมูลหอพักโดย Admin (UC-13)
- การจัดการข้อมูลหอพักของเจ้าของหอพักรายอื่น
