# แผนทางเทคนิค: ดูสถิติหอพัก

ไฟล์ข้อกำหนดอ้างอิง: `spec.md`  
Spec ID: `SPEC-STAT-001` | สถานะข้อกำหนด: `Draft v2`

## 1. สรุปแนวทาง

1. สร้างโมดูลสถิติหอพักสำหรับเจ้าของหอพักที่เข้าสู่ระบบแล้วและเป็นเจ้าของข้อมูลที่ต้องการดู (`CON-AUTH-01`, `FR-STAT-01`)
2. สร้างหน้า dashboard ที่แสดงสถิติเบื้องต้นแบบแบ่งส่วน/กราฟ เพื่อให้เห็นภาพรวมและอ่านง่าย (`FR-STAT-02`, `CON-UI-01`, `ASM-03`)
3. เพิ่มตัวเลือกวันที่เริ่มต้น-สิ้นสุด และนับรวมทั้งสองวันที่ในการคำนวณ พร้อมรองรับ empty state เมื่อไม่มีข้อมูล (`FR-STAT-04`, `FR-STAT-05`, `FR-STAT-06`, `ASM-04`, `ASM-08`)
4. ดึงข้อมูลสถิติจากแบบรายวัน/รายช่วงเวลา สำหรับผู้เข้าชมและการนัดหมาย และแสดงสถานะห้องพักปัจจุบันแยกจากข้อมูลช่วงเวลา (`FR-STAT-03`, `FR-STAT-05`, `ASM-05`)
5. วางโครง API กราฟและรายงานให้ตรวจสอบ Acceptance Criteria ทั้งหมด รวมถึงข้อกำหนดเวลาแสดงผลภายใน 3 วินาที (`NFR-PERF-01`, `AC-STAT-01` ถึง `AC-STAT-05`)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้า dashboard และ form เลือกช่วงเวลา แบบ responsive ตาม `CON-UI-01` และ `NFR-USE-01` |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้าง API สำหรับดึงสถิติหอพักและข้อมูลห้องพักที่เกี่ยวข้อง |
| ฐานข้อมูลเชิงสัมพันธ์ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บข้อมูลหอพัก ห้องพัก สถานะห้องพัก การเข้าชมหน้ารายละเอียดหอพัก และการนัดหมาย |
| Chart library สำหรับกราฟ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างกราฟหรือการแบ่งส่วนเพื่อความเข้าใจง่าย ตาม `FR-STAT-02` และ `CON-UI-01` |
| Export report file (CSV/PDF) | `ASM-06` | ยังรอการยืนยันจากทีมก่อนกำหนด format ตายตัว และจะสร้างไฟล์รายงานจากข้อมูลสถิติที่ query ได้ตามช่วงเวลาที่เลือก |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `Dormitory` | `id`, `owner_id`, `name`, `status` | `FR-STAT-01`, `CON-AUTH-01` |
| `Room` | `id`, `dormitory_id`, `status`, `updated_at` | `FR-STAT-03`, `ASM-02`, `ASM-05` |
| `DormitoryVisit` | `id`, `dormitory_id`, `visited_at` | `FR-STAT-02`, `FR-STAT-05`, `ASM-05` |
| `Appointment` | `id`, `dormitory_id`, `created_at`, `status` | `FR-STAT-02`, `FR-STAT-05`, `ASM-05` |

กติกาข้อมูล:

- `Room.status` จะใช้เฉพาะค่า `ห้องว่าง` และ `ห้องเต็ม` เท่านั้น (`FR-STAT-03`)
- จำนวนผู้เข้าชมและจำนวนการนัดหมาย จะคำนวณจากช่วงวันที่ที่เลือก โดย query จากข้อมูล `DormitoryVisit` และ `Appointment` ตาม `FR-STAT-05`, `ASM-04`, `ASM-05`
- จำนวนห้องว่างและห้องเต็ม จะแสดงตามสถานะปัจจุบันของห้องพัก ไม่ใช่ตามช่วงเวลา (`FR-STAT-05`, `ASM-05`)
- ข้อมูลสถิติให้แยกตาม `dormitory_id` เพื่อป้องกันความคลาดเคลื่อนจากเจ้าของหอพักคนอื่น (`CON-AUTH-01`)
- การดาวน์โหลดรายงานสถิติจะสร้างจากข้อมูลสถิติที่ query ได้ตามช่วงเวลาที่เลือก และยังไม่กำหนด format ตายตัวจนกว่าทีมจะยืนยัน (`ASM-06`)

## 4. API / หน้าจอ

| รายการ | Input หลัก | Output หลัก | รองรับ |
|---|---|---|---|
| `GET /dormitories/{dormitoryId}/statistics` | `dormitoryId`, `startDate`, `endDate` | สรุปสถิติแบบ cards/graph สำหรับห้องว่าง, ห้องเต็ม, ผู้เข้าชม, การนัดหมาย | `FR-STAT-01`, `FR-STAT-02`, `FR-STAT-05`, `AC-STAT-01` |
| `GET /dormitories/{dormitoryId}/rooms/status` | `dormitoryId` | จำนวนห้องว่างและห้องเต็มตามสถานะปัจจุบัน | `FR-STAT-03`, `AC-STAT-02` |
| `GET /dormitories/{dormitoryId}/statistics/date-range` | `dormitoryId`, `startDate`, `endDate` | จำนวนผู้เข้าชมและการนัดหมายตามช่วงเวลา | `FR-STAT-04`, `FR-STAT-05`, `AC-STAT-03` |
| `GET /dormitories/{dormitoryId}/statistics/report` | `dormitoryId`, `startDate`, `endDate` | ไฟล์รายงานสถิติที่สร้างจากข้อมูลสถิติที่ query ได้ | `AC-STAT-05`, `ASM-06` |
| หน้า dashboard | เลือกช่วงวันเริ่มต้น/สิ้นสุด, ปุ่มยืนยัน, ปุ่มดาวน์โหลด | empty state, graph, KPI cards, message “ยังไม่มีข้อมูลสถิติในรอบเวลานี้” | `FR-STAT-01`, `FR-STAT-02`, `FR-STAT-04`, `FR-STAT-06`, `NFR-USE-01`, `AC-STAT-04` |

หมายเหตุ: ชื่อ path และฟิลด์เป็นสัญญาเชิงตรรกะสำหรับการวางแผน ใบนี้ใช้ตามข้อกำหนดเท่านั้น และต้องยืนยันกับทีมก่อนลงมือสร้างจริงหากต้องการรายละเอียดเชิงเทคนิคเพิ่มเติม โดยเฉพาะเรื่อง format ของไฟล์รายงานซึ่งยังรอการยืนยันจากทีม (`ASM-06`)

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| `CON-UI-01` | dashboard, KPI cards, chart, form เลือกช่วงเวลา, empty state และการออกแบบที่เข้าใจง่าย | ใช้แล้ว |
| `CON-AUTH-01` | ต้องตรวจว่า `owner_id` ของผู้ใช้ตรงกับ `Dormitory.owner_id` ก่อนเรียกดึงสถิติหรือ report | ใช้แล้ว |

## 7. ลำดับงาน

1. กำหนด contract สำหรับข้อมูลห้องพักและสถิติที่ใช้บน dashboard ตาม `FR-STAT-02`, `FR-STAT-03`, `FR-STAT-05` และ `CON-AUTH-01`
2. สร้าง service/auth check สำหรับเจ้าของหอพักที่เข้าถึงข้อมูลหอพักที่ถูกต้องตาม `CON-AUTH-01` และ `FR-STAT-01`
3. สร้าง API สำหรับดึงข้อมูลสถิติเบื้องต้นตามช่วงวันที่และข้อมูลห้องพักปัจจุบันตาม `FR-STAT-02`, `FR-STAT-03`, `FR-STAT-04`, `FR-STAT-05`
4. สร้างหน้า dashboard พร้อม form เลือกวันที่และแสดง KPI cards/graph ตาม `FR-STAT-01`, `FR-STAT-02`, `FR-STAT-04`, `CON-UI-01`, `NFR-USE-01`
5. เพิ่ม empty state เมื่อไม่มีข้อมูล และ message แจ้งเตือนตาม `FR-STAT-06`, `AC-STAT-04`
6. เพิ่มฟังก์ชันดาวน์โหลดรายงานสถิติตามช่วงเวลาที่เลือก ตาม `AC-STAT-05`, `ASM-06`
7. ทดสอบ behavior ตาม `AC-STAT-01` ถึง `AC-STAT-05` และตรวจสภาพความเร็วตาม `NFR-PERF-01`
8. ตรวจการใช้งานบนโทรศัพท์ แท็บเล็ต และเดสก์ท็อป ตาม `NFR-USE-01` และตรวจ reliability ของกราฟ/empty state แสดงผลถูกต้องเมื่อมีข้อมูลและเมื่อไม่มีข้อมูล

## 8. สิ่งที่ยังไม่ทำ

- ไม่มี Open Questions ค้างอยู่ใน `spec.md` ปัจจุบัน จึงไม่มีข้อที่ต้องหยุดรอคำตอบก่อนเริ่มสร้าง
- รายละเอียด format ของไฟล์ดาวน์โหลดรายงาน (เช่น CSV/PDF) ยังไม่ได้ระบุชัดเจนใน spec และถูกระบุเป็น Assumption (`ASM-06`) จึงยังรอการยืนยันจากทีมก่อนลงรายละเอียดเชิงเทคนิคจริง
- ส่วนที่เกี่ยวข้องกับข้อมูลห้องว่าง/เต็มและสถิติผู้เข้าชม/การนัดหมายจะยังไม่สร้างฟิลด์หรือการคำนวณเพิ่มเติมนอกเหนือจากสิ่งที่ระบุใน `FR-STAT-02` ถึง `FR-STAT-06`
